## 使用规则

1. **整体复制迁移**：新项目把 `guides/` 整个目录带走，指南之间的《书名号》引用随目录整体迁移，永远有效。
2. **主大纲是入口**：按五档节奏逐档回答「核心问题」、留出「验收证据」；条目标「→ 见专题指南」的，以专题指南为准。
3. **专题指南是深水区**：主大纲只列准入问题；每个专题的全部检查清单、根因表和验收矩阵在专题指南里。
4. **跨项目资产同规则**：组件库（`ui/`）按《多平台一致组件库方案》《公共函数与Helper方案》在本库积累；`lib-go/` 是各新项目在项目期自行建立的 Go 公共库，本库不含该目录。复制迁移与回流纪律同本库。
5. **版本发布记录**：本库的变更按双语格式记录于 [RELEASES.md](./RELEASES.md)；v1.11.0 起统一为四段（**新增 / 修改 / 修复 / 删除**，英文 Added / Changed / Fixed / Removed），空段写「（无 / none）」；更早版本保留当时的格式，不回改历史。
6. **证据等级**：专题里的技术断言分四类——框架源码实证 / 主大纲二手结论 / 行业通行做法 / 法律合规条款。引用二手结论或未核实的框架行为时必须标 `**待验证**`；法律条款由法务确认，工程不得自行判定。
7. **条件性专题与权威归属**：按上方两节执行；触发条件未达成时不进入必答清单，跨域主题以权威篇为准。

## 新增专题指南的约定

- 文件名 = 主题名，放 `专题/<主题>/`：既有主题目录直接归入，新主题（如 `打包分发`、`自动更新`）再开新目录；涉及具体框架的深坑写进对应专题，通用原则写进主大纲。
- 结构遵循三种骨架之一：**纪律母法型**（这份方案是做什么的 → 先让 AI 回答的 10–12 问 → 核心纪律 → 常见根因表 → 测试矩阵 → 实施约束模板 → 五档定位）、**实现配套型**（定位与硬性目标 → 核心设计 → 验收清单 → 实施约束模板 → 五档定位，必须声明母法方案）或 **实证复盘型**（这份复盘是什么 → 时间线/证据链 → 失效分析 → 修复顺序建议 → 验收模板 → 边界声明，须声明母法方案）。章节标题允许描述性变体（「常见根因表」也可写作「XX 问题的常见根因」）；「实施约束模板」为必备段落，实证复盘型可不带「五档定位」。
- 收录新指南时同步更新本清单；删条目或改语义时检查其他指南的《书名号》引用。
- 项目实战教训（哪个项目踩了什么坑）不写进指南正文——指南保持通用，教训进各项目自己的文档。
- 本 README 双语维护：`README.md`（中文）与 `README.en.md`（English）互为镜像，收录、删除或修改指南时两份同步更新。

# WebView2 运行时与图形可靠性方案：Windows 专用规划方案

## 定位与硬性目标

来源：主大纲二档「WebView2 运行时版本契约」「混合 DPI 与跨 GPU 窗口可靠性」「WebView ProcessFailed 恢复」「多窗口 WebView2 内存策略」「混合 DPI 坐标空间」等 Windows 专项条目。母法方案：《窗口与多窗口技术方案》（窗口状态机与几何）、《系统能力与平台集成技术方案》（能力矩阵与降级）、《性能与资源基线技术方案》（内存与 NFR）、《生产构建安全基线方案》（形态差异）、《CI矩阵与质量门禁方案》（矩阵与冒烟）。

本方案只管 **Windows 上 WebView2 作为渲染宿主时的特有风险**：运行时怎么保证装完就能跑、混合 DPI/多 GPU 下不白屏、渲染进程死了怎么恢复、多窗口的内存怎么回收。Linux 基线是 Ubuntu 26.04 自带 GTK4 + WebKitGTK 6.0（主大纲已声明不做多发行版矩阵），macOS 用 WKWebView，两者不适用本文的 WebView2 专有结论。

**硬性目标**：

1. 「装完一定能运行」有明确的分发决策与离线/企业环境验证；
2. 混合 DPI、跨 GPU、RDP 中途 DPI 变化有配置值 + 冒烟记录，不是靠用户反馈发现；
3. 渲染进程失败有恢复流程、重试上限与明确终态；
4. 每个窗口标明常驻/一次性，并据此决定 WebView2 环境共享或独立。

不预设：Evergreen/Fixed Version 选择、具体配置项名、窗口清单。所有框架行为按锁定版本核实，未核实的标**待验证**。

## 开始写代码前，先让 AI 回答这些问题

1. WebView2 运行时选 Evergreen（随系统更新）还是 Fixed Version（随应用打包）？离线/企业禁用自动更新的环境怎么保证「安装后一定能运行」？
2. 若选 Evergreen，检测失败/版本过低时的用户提示与安装引导是什么？是否允许静默降级？
3. 目标用户是否有多显示器、混合 DPI 或双显卡 + 外接屏？混合 DPI 拖拽可能触发渲染进程崩溃/白屏，实测计划是什么？
4. 跨 GPU 适配器切换时控制器是否失效？`UseVisualHosting` 一类缓解开关在锁定版本里的准确名字、默认值与副作用是什么（**待验证**：不同框架版本差异大）？
5. RDP 会话中途 DPI 变化是否需要专门冒烟？配置值在生产构建里是否显式设定？
6. 窗口位置/尺寸是否按「屏幕标识 + DIP 坐标 + 缩放因子」持久化，而非裸像素（→《窗口与多窗口技术方案》）？
7. 渲染进程死亡后注册了什么恢复回调？恢复路径本身是否有重试上限、配置失败不杀宿主、耗尽后有明确终态？
8. WebView2 是**进程组模型**：哪些窗口常驻、共享同一环境以复用进程？哪些一次性、独立环境且用后销毁以确定性回收内存？
9. 内存基线：空闲/多窗口/长时间运行的目标值是多少，谁测（→《性能与资源基线技术方案》）？
10. 这些结论是否只在 dev 构建验过？打包安装形态下重跑了吗（→《生产构建安全基线方案》）？
11. CI 的 Windows runner 是否覆盖混合 DPI 与跨屏场景？若无，手工验收矩阵怎么补？
12. 失败时的用户可理解提示与恢复入口是什么（→《操作反馈方案》）？

交付给 AI 的设计结果应包含：运行时分发决策、配置值表、窗口清单与环境策略、恢复流程图、几何 schema、冒烟矩阵与 NFR 数值。

## 核心纪律

### 一、运行时版本契约

| 选项 | 适用 | 代价 | 必须验证 |
|---|---|---|---|
| Evergreen | 联网、允许系统级更新的普通用户 | 依赖机器上已装运行时；企业可能锁版本 | 未安装/版本过低/更新中被占用三种场景 |
| Fixed Version | 离线、内网、受管设备、要求可复现 | 安装包变大、需自行随应用更新运行时 | 打包产物确实携带运行时；路径与加载方式 |

- 「装完一定能运行」是**产品承诺**，不能靠「一般机器上都有」；决策记录要写明目标环境的约束与验证方式。
- 检测失败不得静默改写成「没有 WebView」后继续走白屏路径；给出明确提示与安装/修复入口。
- 应用自身不擅自安装或覆盖系统级运行时；是否引导用户安装由产品决定（→《系统能力与平台集成技术方案》的降级三档）。
- 运行时版本与框架版本、应用版本一起进产物清单（→《版本号方案》《产品身份单一源方案》）。

### 二、混合 DPI / 跨 GPU / RDP

| 风险 | 判据 | 缓解与验证 |
|---|---|---|
| 混合 DPI 拖拽白屏 | 跨不同缩放显示器拖动后窗口渲染与通信仍正常 | 显式配置缓解开关（按锁定版本核实名字）+ 跨屏拖动冒烟 |
| 跨 GPU 适配器切换 | 外接屏/独显切换后控制器仍可用 | 目标硬件组合冒烟 + 失败时的重建路径 |
| RDP 中途 DPI 变化 | 会话中改变缩放后不白屏、不错位 | 特定 hosting 配置值（待验证）+ RDP 冒烟 |
| 坐标口径撕裂 | 多屏下位置恢复正确 | 屏幕标识 + DIP + 缩放因子，`0,0` 不作哨兵（→《窗口与多窗口技术方案》《托盘技术方案》） |

**配置值必须显式写进生产构建**，不能依赖「默认就好」。任何缓解开关都有代价（渲染方式、输入、无障碍），属于改变用户可感知行为的产品决策，要记录用户确认与已知代价（→《托盘技术方案》「换显示后端是有代价的产品决策」同理）。

### 三、ProcessFailed 恢复

```
检测进程失败 → 记录可诊断现场（不含用户数据）
  → 尝试恢复（有上限 N，退避）
    → 成功：重建后按几何落盘摆位，回到统一唤回流程
    → 失败：不杀宿主进程，展示明确终态与手动重试入口
```

四条纪律：

- 恢复回调必须注册且只有一处主人（→《托盘技术方案》的回调注册唯一性纪律）；
- 恢复路径有重试上限与终态，避免无限重建把内存打爆；
- 配置失败/恢复失败不杀主进程，用户至少能看到错误与「重试」；
- 每次恢复留可诊断记录（关联 ID、次数、结果），供复盘（→《日志与可诊断性技术方案》）。

### 四、多窗口内存策略

| 窗口类型 | 环境策略 | 理由 |
|---|---|---|
| 常驻（主窗口、长期面板） | 共享同一 WebView2 环境/进程组 | 复用进程，降低常驻内存 |
| 一次性（临时预览、向导、详情） | 独立环境 + 用后销毁 | 确定性回收，避免临时窗口内存不释放 |

窗口清单逐项标注常驻/一次性、环境共享/独立、销毁时机、几何归属。长时间运行后测内存曲线，而不是只看启动瞬间（→《性能与资源基线技术方案》）。隐藏窗口是否继续存活 WebView 也要写明（→《窗口与多窗口技术方案》的隐藏/销毁语义）。

## 常见根因表

| 表面现象 | 常见根因 | 开始实现前的预防 |
|---|---|---|
| 企业内网安装后白屏 | Evergreen 运行时缺失/被锁版本，无检测与引导 | 运行时分发决策 + 离线场景验证 |
| 跨屏拖动后白屏/渲染进程崩 | 混合 DPI 未显式配置缓解开关 | 配置值 + 跨屏拖拽冒烟 |
| 外接屏切换后控制器失效 | 跨 GPU 适配器切换 | 目标硬件冒烟 + 重建路径 |
| 渲染进程死后永久空白 | 无恢复回调，或恢复无上限反复重建 | 回调唯一 + 重试上限 + 明确终态 |
| 多窗口越用越占内存 | 常驻/一次性未分，环境策略一刀切 | 窗口清单 + 共享/独立决策 |
| 多屏恢复位置错位 | 用裸像素、零值当哨兵 | 屏幕标识 + DIP + 缩放因子 |
| dev 正常、安装包异常 | 配置只在 dev 构建生效 | 生产配置显式 + 安装态冒烟 |

## 先设计测试矩阵，再开始实现

| 维度 | 要覆盖 |
|---|---|
| 运行时 | 已装/未装/过低/更新中/企业锁版本；Evergreen 与 Fixed Version 各自验证 |
| DPI/GPU | 单屏、混合 DPI、跨屏拖动、独显/核显切换、RDP 中途缩放变化 |
| 恢复 | 单次失败恢复、连续失败到上限、配置失败、终态提示与重试 |
| 内存 | 空闲、多窗口、长时间运行、一次性窗口关闭后回落 |
| 几何 | 主屏/副屏、最大化、坐标口径、`0,0` 合法值 |
| 形态 | dev / 打包安装分别重跑；CI 无覆盖的写手工验收 |
| 门禁 | 故意制造一次渲染失败，确认恢复与终态可观察 |

## 给 AI 的实施约束模板

> 先给出 WebView2 运行时分发决策（Evergreen/Fixed Version 及离线验证）、显式配置值表、窗口清单（常驻/一次性 + 环境共享/独立）、ProcessFailed 恢复流程图与几何 schema，再写窗口初始化代码。**装完一定能运行要有目标环境验证；显式配置缓解开关而不是依赖默认值；恢复回调唯一且带重试上限与明确终态；配置/恢复失败不杀宿主；几何按屏幕标识 + DIP + 缩放因子持久化；所有结论在打包安装形态下重跑。** 配置项名与默认值按锁定框架版本源码核实，查不到证据的写「待验证」，不得照抄其他版本；换显示/托管方式属于改变用户可感知行为的产品决策，须记录确认与已知代价。实现后给出可观察冒烟记录与内存曲线，并列出未实测硬件组合。所有窗口分类、阈值、配置值由当前项目需求决定。

| 档位 | 本方案承担 |
|---|---|
| 一档 | 运行时分发决策（装完能运行）、显式配置原则 |

| 三档 | 内存曲线实测、失败提示与重试入口 |

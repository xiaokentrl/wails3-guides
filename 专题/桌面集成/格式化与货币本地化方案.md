# 日期、数字与货币本地化：通用规划方案

## 这份方案是做什么的

《国际化与输入技术方案》定了「数据归数据、展示层集中格式化」；《多语言实现方案》定了 Intl 单点与语言切换。本方案给出**格式化单点的实现规格**：日期/时间/数字/货币/单位/相对时间的全部决策，以及最易翻车的两块——**货币精度**与**时区/夏令时**。

**与相邻方案的分工**：持久化只存规范化值 →《国际化与输入技术方案》；语言切换 →《多语言实现方案》；输入解析的正确性 →《输入数据验证方案》；格式化与排序的引擎差异 →《多平台一致组件库方案》引擎基线。

**硬性目标**：
1. 全库格式化**只有一个模块**（`lib/format`）——组件里手写格式化 = 违规（→ 公共函数方案能力包归属）；
2. **金额永不使用浮点运算**——最小单位整数存储，显示经 minor-unit 换算；
3. **日期解析不依赖本机时区巧合**——纯日期按本地午夜解析、带时区时间戳按 UTC 解析；
4. locale（语言）、region（区域）、currency（货币）、timeZone（时区）**四个上下文分离**，各自显式设置。

## 上下文分离（最先立对的结构）

| 上下文 | 来源 | 说明 |
|---|---|---|
| **locale**（语言标签） | 用户语言设置（→ 多语言方案） | 决定文案语言与默认格式习惯 |
| **region**（区域） | 用户显式设置或派生 | 决定日期/数字格式习惯（zh-CN 用户也可能在美区） |
| **currency**（货币） | **业务决定**（结算币种），不跟随 locale | 中国区看美元价格是合法需求 |
| **timeZone**（时区） | 显式设置 > 设备时区 | 展示时区与存储时区分离 |

**铁律**：`Intl.NumberFormat(locale, { style: 'currency', currency })` 的 currency **必须显式传入**——跟随 locale 会得出「中国用户显示 ¥」这类错误结算。locale 与 region 分离传入（`Intl` 支持 `zh-Hans-u-nu-hanidec` 等扩展，region 用 `-u-rg-` 或显式覆盖）。

## 货币：精度是正确性问题，不是显示问题

- **存储**：金额一律**最小单位整数**（人民币/美元存「分」，日元存「元」）或十进制字符串——**浮点永不参与金额**（`0.1 + 0.2 !== 0.3`；浮点累加对账必错）；
- **显示**：`Intl.NumberFormat(locale, { style: 'currency', currency })`；从最小单位换算主单位时的**小数位数从 Intl 的 `resolvedOptions().maximumFractionDigits` 取**——日元 0 位、美元 2 位、第纳尔 3 位，**不手写除以 100**；
- **结算/显示分离**：结算金额（账单、退款）用精确最小单位；展示舍入（如汇率换算参考价）必须标注「仅供参考」；
- **运算**：金额加减乘除在整数域或 decimal 库，**禁止浮点中间值**；比例/汇率换算的结果落库前按业务规则取整（取整方向登记）；
- **加密货币/自定义单位**：非 ISO 4217 的走自定义符号 + 小数位登记，不复用 currency 管道。

## 日期与时间：解析、存储、显示三段分明

- **存储**：带时刻的时间戳存 UTC epoch（毫秒）；**纯日期（生日、账期）存 `YYYY-MM-DD` 字符串**——存 epoch 会被时区偏移错一天；
- **解析**（输入验证链的一环，→ 输入验证方案）：
  - `YYYY-MM-DD` → `new Date(y, m - 1, d)` **本地午夜**——`new Date('2026-11-05')` 按 UTC 解析，西半球会显示成前一天；
  - 带时区的 ISO → 按其偏移解析；无时区的时间戳 → 按当前 timeZone 上下文解析并标注；
  - 解析失败返回 null 不抛异常（→ 输入验证逐键降级）；
- **显示**：`Intl.DateTimeFormat` 单点；时区显式传上下文值；
- **夏令时**：**禁止用 epoch 加减 24 小时表示「明天同一时刻」**——DST 切换日会出现 23/25 小时；日历运算用日期组件（加天数用 `setDate`），时刻运算才用 epoch；
- **相对时间**：`Intl.RelativeTimeFormat`（「3 天前」），阈值与切换点登记（何时从相对变绝对）；
- **区间**：起止日期的显示含连接符方向适配（RTL）。

## 数字与单位

- 分组、小数位、百分比的区域差异全部交给 `Intl.NumberFormat`（`notation: 'compact'` 做万/千缩写）；
- **单位**：`Intl.NumberFormat({ style: 'unit', unit: 'kilometer' })`——单位随语言本地化（千米/km）；
- **精度**：展示精度与存储精度分离；比例类（进度、百分比）存原始比值；
- **解析**（用户输入数字）：按当前 locale 解析（欧式 `1.234,5`）→ 规范化数值 → 校验（→ 输入验证方案）——**存前必须转规范值**。

## 排序与比较

- 文本排序走 `Intl.Collator`（→ 国际化方案 collation 纪律）；金额/数值排序在原始值上做，不排格式化字符串。

## 测试矩阵

| 维度 | 要覆盖的情况 |
|---|---|
| 货币 | JPY/USD/KWD 三种 minor-unit；结算与显示分离；整数域运算对账 |
| 时区 | UTC±13 边界、跨时区展示同一时间戳、显式时区覆盖 |
| DST | 切换日「明天同一时刻」、本地午夜解析、23/25 小时日 |
| 解析 | `2026-11-05` 在 UTC-8 与 UTC+8 的显示一致；欧式数字输入规范化 |
| locale/region 分离 | zh 语言 + US region 的日期与货币组合 |
| 相对时间 | 阈值切换；RTL 呈现 |
| 回归 | 格式化输出快照（locale × 类型矩阵） |

## 常见根因

| 表面现象 | 常见根因 | 开始实现前的预防 |
|---|---|---|
| 金额对账差 1 分 | 浮点运算 | 最小单位整数 + 整数域运算 |
| 日元显示 0.00 | 手写除以 100 | minor unit 取自 resolvedOptions |
| 中国用户看到美元符号 | currency 跟随 locale | 四上下文分离、显式 currency |
| 生日显示差一天 | `new Date('YYYY-MM-DD')` 按 UTC 解析 | 本地午夜解析 |
| 「明天」缺 1 小时 / 多 1 小时 | epoch 加减 24h | 日历组件运算 |
| 欧式输入 `1.234,5` 变成 1.2345 | 按美式解析 | locale 感知解析 → 规范值 |
| 同一页面两种日期格式 | 组件内手写格式化 | lib/format 单点 + 审计 |

## 给 AI 的实施约束模板

开始实现时，可要求 AI：

> 先给出格式化上下文设计（locale/region/currency/timeZone 四分离、来源与设置接线）。全部格式化收敛到 lib/format 单点并走 Intl；金额最小单位整数存储、显示小数位取自 resolvedOptions、整数域运算禁浮点；纯日期本地午夜解析、时间戳 UTC、DST 用日历组件运算；相对时间与单位走 Intl 相应 API；用户输入数字按 locale 解析后转规范值再校验；currency 显式传入不跟随 locale。组件内手写格式化与裸数字拼接视为违规。实现后补 locale × 类型 × 时区/DST 边界的快照与解析反转测试，并明确列出未覆盖的组合。

方案确认后再改代码；货币与精度规则属业务决策，AI 给方案与推演，最终由用户裁决。

## 五档定位

- **一档**：四上下文分离决策 + 货币精度规则（最小单位） + 时区策略。
- **二档**：lib/format 单点落地、快照测试进 CI。
- **三 / 四档**：DST/时区边界全测、多币种结算、格式化回归快照全量。

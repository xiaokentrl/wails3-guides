# 托盘多语言：Wails3 + Go 专用方案

## 定位与硬性目标

实现配套方案。母法：《多语言实现方案》（语言包 `locales/*.json`、Go 加载器 `T()`、设置单源、切换联动表——本方案不重复其机制，只管**托盘面上语言怎么判定、怎么渲染、怎么切换**）；《托盘技术方案》（托盘入口与身份图标）；《菜单方案》（命令注册表 `LabelKey`）。文案键全部走语言包，本方案零新增文案源。

**硬性目标**：

1. 托盘一切用户可见文字——菜单项、子菜单标题、tooltip、托盘发起的通知与对话框——**随用户设置的语言显示**，与前端语言永远一致（设置单源，不存在「窗口是中文、托盘是英文」）；
2. 切换语言后托盘**重建即时生效**；运行时重建不可行的平台，重启生效并在设置界面明示降级；
3. 首次启动无设置时按系统语言初始化——此后只信设置，托盘不自行探测第二套语言。

## 一、语言判定链（Go 侧唯一解析点）

托盘在 Go 侧渲染，语言由 Go 侧解析——解析只有一处（`i18n` 包的当前语言，→ 多语言方案加载器），判定顺序：

```
1. 持久化设置的语言（规范化 BCP 47，→ 应用状态与持久化方案）
2. 无设置（首次启动）：系统语言探测——
   Windows GetUserDefaultUILanguage / macOS UserDefaults / Linux LC_ALL→LANG
   （探测实现按锁定平台验证，未验证标「待验证」）
3. 探测失败或标签无效 → 基准语言（zh-CN）并记警告日志
```

纪律：

1. **托盘代码不自己判语言**——只调 `T(key, params)`，语言由加载器持有；托盘里出现任何 locale 探测/字符串分支都是缺陷；
2. **设置写入 → 双端同步生效**：前端切语言 = 写设置 = 广播 Go（→ 同步层）→ Go 侧更新加载器当前语言 + 触发托盘重建；**不允许**前端改了、托盘重启才变（除非平台降级，见第三节）；
3. 语言标签在 Go/前端之间只传规范化 BCP 47 字符串（`zh-CN`），不传显示名、不传索引。

## 二、托盘面上要本地化的清单（逐项过，漏一项就是双语混排）

| 面 | 内容 | 文案来源 |
|---|---|---|
| 托盘菜单项 | 唤回/显示主窗口、设置、退出、关于、动态项（暂停同步/继续同步） | 命令注册表 `LabelKey` → `T()`（→ 菜单方案） |
| 子菜单标题 | 语言、主题、最近文件等子菜单 | 同上；**勾选态标记（✓/radio）由原生 API 承担，不写进文案** |
| tooltip | 图标悬停文案（常驻身份提示） | `T()`；tooltip 与菜单**同一重建时机**（很多平台一次 Set 不能只换一半） |
| 托盘发起的系统通知 | 「已在后台运行」「任务完成」等 | `T()`（→ 多语言方案消费方清单） |
| 托盘发起的原生对话框 | 确认退出、错误提示 | `T()`；按钮文案同样键化（双「取消」消歧 → 弹窗按钮文案方案） |
| 不本地化 | 分隔符、图标、快捷键修饰符显示（由平台渲染） | — |

反模式红旗：菜单构建代码里出现 `if lang == "zh"`、中文/英文字面量、按语言拼字符串——全部走键。

## 三、渲染与切换时机（重建的原子性）

**启动时**：`ServiceStartup` 前读设置 → 加载器定语言 → 用该语言构建托盘菜单与 tooltip——首帧前的同步路径，禁慢 I/O（→ 单实例与快速启动方案：读一个小 JSON 属必需阻塞项）。

**运行时切换**：语言变更事件到达 Go 侧后，**先换加载器语言、后重建托盘**——顺序反了会有一瞬间旧语言 tooltip 配新语言菜单。重建以「构建完整新菜单 → 一次原子替换（Wails3 `SetMenu`）」完成，禁止逐项 `UpdateLabel` 半旧半新。

**平台差异表**（Wails3 alpha，逐项按锁定版本验证，未验证一律**待验证**）：

| 平台 | 重建时机 | 已知约束 |
|---|---|---|
| Windows | 即时生效 | 菜单未弹出时替换无感；弹出状态下替换可能不刷新已显示的窗口——重建前若菜单打开，先关闭或延迟到关闭后 |
| macOS | 即时生效（`NSStatusItem` menu 重建） | 菜单**打开期间**不可换内容——切换事件到来时菜单多在打开态（用户正从菜单点设置），延迟到菜单关闭后重建 |
| Linux（AppIndicator） | DBus 重建即时生效 | 某些桌面环境对菜单重建有缓存延迟；不可重建的环境走重启降级 |

**降级声明**：运行时重建验证不通过的平台，降级 = 「重启生效」，且设置页切换语言时**必须明示**「托盘将于重启后更新」——不允许静默降级让用户以为没生效。

## 四、与前端语言的一致性防御

1. **单源**：当前语言只存在设置里一份（→ 多语言方案），Go 加载器与前端 store 都是它的镜像；
2. **一致性自检**：设置变更广播后，Go 侧回执确认（→ 同步层回执纪律）；托盘重建完成的回执进日志（语言标签 + 重建耗时）；
3. **不一致可见即缺陷**：任何「托盘语言 ≠ 前端语言」的状态（如 Go 侧广播丢失、平台降级未声明）按缺陷登记——测试矩阵有一项专测；
4. **RTL**：RTL 语言下原生托盘菜单**多数不可镜像方向**（→ 国际化与输入技术方案原生层限制），保持系统渲染并列入平台差异验证清单，不默认「到时候再说」。

## 测试矩阵

| 维度 | 覆盖 |
|---|---|
| 判定链 | 有设置/无设置/无效标签三分支；首启探测按平台验证（待验证标注） |
| 全覆盖 | 逐项过第二节清单：菜单/子菜单/tooltip/通知/对话框在目标语言下无一英文残留 |
| 切换 | 前端切语言 → 托盘菜单+tooltip 重建为同一语言（先后顺序无闪变）；重建回执入日志 |
| 降级 | 不可重建平台：重启生效 + 设置页明示文案存在（不静默） |
| 一致性 | 托盘语言 = 设置语言 = 前端语言三处相等；广播丢失场景能被回执超时捕获 |
| 键齐性 | 托盘用到的键在发布语言零缺失（多语言方案 CI 门禁同一道闸） |

## AI 约束模板

> 托盘一切用户可见文字（菜单项、子菜单、tooltip、托盘发起的通知与对话框按钮）一律走命令注册表 LabelKey → 语言包 `T()`，托盘代码零语言探测、零字面量分支；勾选态用原生 API 不写进文案。语言判定链：设置（BCP 47 单源）→ 首启系统语言探测（按平台验证，未验证标待验证）→ 基准回退并记警告。切换语言 = 前端写设置广播 Go → 先换加载器语言后重建托盘（先构建完整新菜单再一次原子替换，禁逐项改标签）；tooltip 与菜单同批重建。平台差异（Windows 弹出态、macOS 打开期不可换、Linux DBus 缓存）按锁定版本验证，不可重建走重启降级且设置页必须明示。托盘语言、设置语言、前端语言三处必须恒等，不一致即缺陷。实现后跑测试矩阵并逐平台报告重建验证结论。

## 五档定位

- **一档**：本地化清单逐项对表 + 判定链实现 + 启动语言构建；
- **二档**：运行时切换重建按平台逐一验证（结论回填差异表），降级声明就位；
- **持续**：新增托盘菜单项/tooltip/通知时按第二节清单过键齐性；平台差异表随 Wails3 升级复核。

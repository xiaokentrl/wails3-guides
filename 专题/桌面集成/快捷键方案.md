# 快捷键：Wails3 + Go 专用方案

## 这份方案是做什么的

快捷键横跨三层：命令触发（菜单方案命令注册表的发放端）、界面作用域（表格与编辑器各有按键语义）、操作系统（全局键与保留键）。本方案给快捷键定**全生命周期契约**：怎么分类、在哪注册、冲突怎么判、哪些键碰不得、打字时怎么办、用户怎么发现。

**硬性目标**：全应用的快捷键**只有一个出生地**（注册中心）、**一张总表**（可发现性由总表自动生成）、**零硬编码按键**（组件与页面不自行监听）。

**与相邻方案的分工**：命令与快捷键的对应关系 →《菜单方案》（注册表发放）；全局键的平台仲裁与注册失败 →《系统能力与平台集成技术方案》；IME 组合态基础规则 →《国际化与输入技术方案》；键盘可达底线 →《无障碍与辅助技术方案》。本方案管**分类、注册、冲突、保留键、可发现性**。

## 快捷键四级分类

| 级别 | 何时生效 | 注册位置 | 示例 |
|---|---|---|---|
| **表面级** | 焦点在某表面时 | 注册中心 `scope: surface` | 表格内 `Enter` 打开、编辑器 `Ctrl+S` |
| **应用级** | 应用前台 | 注册中心 `scope: app` | `Mod+O` 打开、`Mod+K` 命令面板 |
| **全局级** | 应用后台也生效 | 系统桥接（→ 系统能力方案） | 全局截图、媒体键 |
| **平台保留** | 永不触碰 | ——禁区 | 见下表 |

## 注册中心（唯一出生地）

```ts
// frontend/…/commands/ —— 消费菜单方案命令注册表（→ 前端目录结构方案）
registerShortcut({
  commandId: 'library.import',      // 快捷键必须绑定命令，无主快捷键不许存在
  key: 'Mod+O',                     // 修饰键令牌：Mod=macOS Cmd / 其余 Ctrl
  scope: 'app',                     // app | surface:<name>
  when: 'canImport',                // 可用条件，与命令 When 同源
  ime: 'allow',                     // 组合态行为：allow | block（默认见下）
})
```

纪律：

- **无主快捷键禁止存在**：每个快捷键绑定一个命令 ID；直接 `addEventListener('keydown')` 的散装监听是禁区（grep 审查零例外）。
- **冲突在注册期即报错**：同 scope 同 key = 构建期/开发期错误；跨 scope 同 key 合法——**解析优先级：表面级 > 应用级**，焦点所在表面优先。
- **修饰键只用令牌**：`Mod / Shift / Alt / Cmd / Ctrl`；任何字面量 `event.ctrlKey` 出现在组件里即违规（跨平台显示错位的根源）。
- **总表自动生成**：帮助浮层、菜单项显示、命令面板检索全部读注册中心——快捷键改动只发生一处，三处显示自动一致。

## 平台保留键禁区（碰不得清单）

| 类别 | 例 | 后果 |
|---|---|---|
| 系统导航 | `Cmd+Tab`、`Alt+Tab`、`Alt+F4`、Win 键组合 | 抢占无效或破坏系统习惯 |
| 输入法切换 | `Ctrl+Space`、`Cmd+Space`、`Shift`（部分 IME） | **CJK 用户打字首选冲突源**，默认回避 |
| 系统服务 | Spotlight、全局搜索、截屏、音量 | 注册失败或被系统裁决（→ 系统能力方案） |

清单随平台核实补充（待验证项标注）；保留键相邻的「安全键位」也要慎选（如 `Mod+Q` 在 macOS 是退出，重新绑定属用户习惯变更需确认）。

## IME 组合态（CJK 产品的必修规则）

- **默认 `block`**：组合态（用户正在打拼音/假名）期间，除显式声明的 `allow` 白名单外，全部应用级快捷键不触发——「打字打到一半跳窗」是 CJK 用户最恨的缺陷。
- `allow` 白名单从严：仅放行明确安全项（如 Esc 退出组合）；逐项登记。
- 与国际键盘布局差异一并验证（→ 国际化方案测试矩阵）。

## 序列键（chord）与自定义

- **序列键**（`Mod+K` → `Mod+S`）：支持与否立项决策；启用则注册中心管序列状态与超时（800ms 量级），超时回落为无操作，菜单显示按平台惯例格式化。
- **用户自定义重绑**：默认**暂缓**（五档记录触发条件：面向高级用户/专业工具时再做）；启用则绑定存设置（→ 状态方案）、改绑冲突当场提示、提供恢复默认。
- **全局键**一律默认关闭 + 用户显式开启（占用系统资源与用户习惯，→ 系统能力方案注册失败备选）。

## 可发现性（快捷键不为记忆服务）

- 菜单项自动显示快捷键（读注册中心，含平台修饰键渲染 → 菜单方案）。
- `Mod+/`（或 `?`）唤出**快捷键总表浮层**：内容自动从注册中心生成，**零手维护**——总表漏项 = 注册中心漏登记，一查便知。
- 命令面板可按快捷键搜索；按钮 Tooltip 显示作用域快捷键。

## 测试矩阵

| 维度 | 要覆盖的情况 |
|---|---|
| 注册 | 重复键报错；跨 scope 覆盖优先级；总表与注册中心一致性 |
| 平台 | 三平台修饰键渲染与实际键位；保留键清单逐一确认未触碰（待验证项实机核） |
| IME | CJK 输入法组合态打全程 → 无误触发；`allow` 白名单逐项验证 |
| 作用域 | 焦点切换后表面级生效/失效；模态下应用级是否放行（决策记录） |
| 全局 | 三平台注册成功/被占用/用户拒绝三路（→ 系统能力方案） |
| 序列 | 序列超时回落；序列中取消 |
| 发现 | 总表覆盖数 = 注册中心登记数；菜单/面板/Tooltip 显示一致 |

## 常见根因

| 表面现象 | 常见根因 | 开始实现前的预防 |
|---|---|---|
| 快捷键互相打架 | 散装监听、无冲突检测 | 唯一注册中心 + 注册期报错 |
| 打中文时窗口乱跳 | 组合态未拦截 | IME 默认 block + 白名单 |
| macOS 显示 Ctrl | 修饰键硬编码 | Mod 令牌 + grep 审查 |
| 总表漏了新功能 | 总表手维护 | 总表自动生成 |
| 抢了系统键用户发现系统失灵 | 保留键清单缺失 | 禁区清单 + 实机核验 |
| 全局键注册失败无感知 | 静默吞 | 失败提示 + 备选键位 |
| 改键后菜单还是旧显示 | 多处定义 | 总表/菜单读注册中心 |

## 给 AI 的实施约束模板

开始实现时，可要求 AI：

> 全部快捷键经注册中心声明（commandId / key 用修饰键令牌 / scope / when / ime），绑定命令 ID，无主快捷键与散装 keydown 监听禁止存在；重复键注册期报错，表面级 > 应用级解析；平台保留键禁区清单先核实再定键位，IME 切换键回避；组合态默认 block、白名单从严逐项登记；帮助总表与菜单显示自动生成、零手维护；全局键默认关闭走系统能力方案；序列键与用户重绑按立项决策，未决策不实现。实现后跑测试矩阵，并明确列出未覆盖的平台与键位组合。

方案确认后再改代码；保留键行为与序列键惯例随平台差异先实机验证，未验证标注待验证。

## 五档定位

- **一档**：键位设计原则 + 保留键禁区清单 + 注册中心选型（与《菜单方案》同批，大纲准入条目在二档「命令与菜单体系」）。
- **二档**：注册中心 + 命令绑定 + IME 默认拦截 + 总表自动生成。
- **三 / 四档**：序列键、全局键、用户重绑（按决策）全量验证。

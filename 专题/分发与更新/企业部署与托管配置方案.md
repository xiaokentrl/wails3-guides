# 企业部署与托管配置方案：通用规划方案

## 这份方案是做什么的

来源：主大纲五档「企业批量部署」暂缓项（原话：当首个企业客户要求批量部署时，评估企业分发路径和杀软白名单提前量）、企业桌面分发实践（MSI/PKG 静默参数、Intune/GPO/Jamf/MDM、可禁用自动更新的管理策略、更新环与回滚组）、以及《默认安装目录规划方案》《签名打包与更新分发技术方案》《配置文件方案》里与「管理员替用户决定」相关的片段。

母法方案：《默认安装目录规划方案》（每用户/每机器目录）、《配置文件方案》（托管配置与逐键降级）、《签名打包与更新分发技术方案》（包格式与更新）、《供应链安全与依赖治理方案》（白名单与 EDR）、《生产构建安全基线方案》（代理/证书）、《遥测与隐私合规方案》（DPA 与子处理者）。

它管**「企业 IT 替几百台机器装、管、更新、卸载」时应用必须提供的契约**：静默安装、托管策略、更新环、卸载净空、离线/内网分发。不预设：企业是否出现、包格式、MDM 厂商、策略键名。

## 开始写代码前，先让 AI 回答这些问题

1. 是否真的需要企业批量部署？触发条件（首个企业客户）是否写进立项包（→《立项范围与决策记录方案》）？
2. 每个平台的分发包格式是什么：Windows MSI（或 MSIX）、macOS 签名 PKG、Linux deb/rpm？静默参数分别是什么，退出码是否可靠？
3. 安装范围：per-user 还是 per-machine？无管理员权限时能否安装？升级时旧版本路径如何处理（→《默认安装目录规划方案》）？
4. 静默安装是否需要应答文件/转换（MST）？自定义属性有哪些（安装目录、是否创建快捷方式、是否禁用自动更新、代理设置）？
5. 托管配置（managed preferences）如何下发：Windows GPO/注册表策略、macOS 配置描述文件、Linux 配置文件？应用如何读取并**与用户偏好仲裁**？
6. 管理员能否禁用自动更新、锁定更新通道、指定更新服务器？用户显式设置与托管策略冲突时谁赢（→《托盘技术方案》「用户显式设置不应被应用覆盖」同理）？
7. 企业内网/气隙环境：运行时依赖（WebView2 Evergreen/Fixed Version）、许可证激活、更新包如何离线交付（→《WebView2运行时与图形可靠性方案》《授权与许可方案》）？
8. 更新环与回滚：pilot / broad / rollback 分组如何定义？ESR 类长期分支是否需要，重叠期提前多久（→《签名打包与更新分发技术方案》）？
9. 杀软/EDR 白名单按证书还是哈希提交？提前量多少（→《供应链安全与依赖治理方案》）？
10. 卸载是否净空且不删用户数据？托管策略残留、服务、计划任务、协议注册如何清理（→《默认安装目录规划方案》）？
11. 日志与诊断：企业要求的日志位置、级别、留存、导出路径是否可配置且不违反脱敏规则（→《日志与可诊断性技术方案》）？
12. 客户安全问卷/DPA、子处理者清单、数据驻留要求是否已准备（→《遥测与隐私合规方案》）？
13. 部署演练：在干净机器、域环境、无网络环境各跑一遍安装→升级→回滚→卸载的记录在哪？

交付给 AI 的设计结果应包含：包格式与静默参数表、安装范围与权限、托管配置键与仲裁规则、更新环与回滚、离线分发、白名单、卸载净空、演练记录。

## 核心纪律

### 一、静默安装是可测试的契约

| 平台 | 包格式 | 必须验证 |
|---|---|---|
| Windows | MSI（/qn /norestart /l*v 日志）或 MSIX | 退出码、日志留痕、无界面、装完不自动重启、检测规则 |
| macOS | 签名 PKG | 静默安装、MDM 分发、公证与沙盒约束（→《商店分发与沙盒合规方案》） |
| Linux | deb/rpm（Ubuntu 26.04 基线） | 非交互安装、依赖解析、服务单元启用状态 |

- 不同打包器的静默参数不一致，**不能凭经验拼**；在测试机上打印支持的参数并写进文档。
- 部分 EXE 安装器即使成功也返回非 0 退出码：企业部署平台依赖退出码判定合规，必须实测并把例外写清。
- 安装日志是企业排障与审计依据，路径可配置且不含敏感值。
- 每用户/每机器的目录、权限、快捷方式、协议注册要分别验证；升级时不得把用户数据写到新的位置后「看起来丢了」（→《默认安装目录规划方案》）。

### 二、托管配置：单一仲裁规则

| 项 | 规则 |
|---|---|
| 来源 | 托管策略（GPO/MDM/配置文件）与用户偏好各自独立读取 |
| 优先级 | **仅管理员明确锁定的键**：托管策略 > 用户偏好，被锁定项在 UI 显示「由组织管理」且不可改；**未锁定的用户显式设置，应用不得覆盖**（→《托盘技术方案》）。锁定/非锁定键清单写入托管配置契约 |
| 未知键 | 逐键降级报错，不因一个陌生键整体白屏（→《配置文件方案》） |
| 缺省 | 未下发时走产品默认，不写死企业特定值 |
| 变更 | 运行中策略变化是否生效、何时生效、是否需要重启，逐项写明 |
| 审计 | 策略来源与生效值可诊断，不含用户内容（→《日志与可诊断性技术方案》） |

**裁决规则**：托管策略优先仅适用于管理员明确锁定的键；对未被锁定的用户显式设置，应用不得覆盖，也不得借「企业策略」名义悄悄改写（→《托盘技术方案》）。「禁用自动更新」属于锁定键，需在 UI 与托管契约中明示。

### 三、更新环、回滚与离线

- 通道（stable/beta/ESR 类）与部署分组（pilot → broad → 回滚组）在打包前定义，而不是出事时临时挑机器（→《版本号方案》《签名打包与更新分发技术方案》）。
- 企业可指定更新服务器/镜像、禁用自动更新、延迟安装；这些是托管键，不是命令行彩蛋。
- 回滚包与旧版本保留期、验证流程写进 runbook；跨卷更新/路径差异的演练见《签名打包与更新分发技术方案》。
- 气隙环境：运行时、许可激活、更新包三类依赖各有离线交付路径（→《WebView2运行时与图形可靠性方案》《授权与许可方案》）；代理/自定义 CA 走《生产构建安全基线方案》的策略。

### 四、白名单、卸载与文档

- 白名单按证书或哈希向安全厂商提交，**提前量写进发布计划**；签名不等于不被启发式拦截（→《供应链安全与依赖治理方案》）。
- 卸载净空：程序文件、服务/计划任务、协议注册、托盘项、缓存按契约清除；用户数据与托管策略残留的处理明确写出，不能「一刀切全删」（→《默认安装目录规划方案》）。
- 交付给企业的文档：静默参数、托管键清单、日志位置、更新/回滚流程、卸载行为、DPA 与子处理者清单（→《用户文档与上手支持方案》《遥测与隐私合规方案》）。

## 常见根因表

| 表面现象 | 常见根因 | 开始实现前的预防 |
|---|---|---|
| 500 台机器同时弹出安装向导 | 静默参数写错或打包器不支持 | 测试机实测参数 + 退出码 + 日志留痕 |
| 部署平台显示失败但应用装好了 | 安装器返回非 0 退出码 | 实测退出码并写例外 |
| 企业策略下发后被用户设置覆盖 | 无仲裁规则 | 仅管理员明确锁定的键优先 + UI 标注「由组织管理」；未锁定的用户显式设置不得覆盖 |
| 一个陌生策略键导致白屏 | 配置整体解析失败 | 逐键降级（→《配置文件方案》） |
| 内网机器装完白屏 | Evergreen 运行时缺失 | Fixed Version 或离线分发（→《WebView2运行时与图形可靠性方案》） |
| 禁用自动更新却仍在下载 | 开关只在 UI，未进执行点 | 托管键在执行点统一校验 |
| 签名包仍被 EDR 拦截 | 以为签名等于白名单 | 提前提交 + 目标软件实测 |
| 卸载后残留服务/协议注册 | 无卸载契约演练 | 卸载净空清单 + 演练记录 |

## 先设计测试矩阵，再开始实现

| 维度 | 要覆盖 |
|---|---|
| 安装 | 每用户/每机器、有/无管理员、静默参数、退出码、日志、重启行为 |
| 升级 | 旧版 → 新版数据保留、路径不变、托管策略继承 |
| 策略 | 全部键、未知键、锁定键 UI 表现、运行中变更、缺省行为 |
| 更新 | pilot/broad/回滚、禁用自动更新、指定服务器、离线包 |
| 网络 | 代理、自定义 CA、气隙、EDR 拦截 |
| 卸载 | 净空清单逐项核对、用户数据保留、二次安装 |
| 演练 | 干净机器、域环境、无网络三种环境全流程 |

## 给 AI 的实施约束模板

> 先给出包格式与静默参数表、安装范围与权限、托管配置键与仲裁规则、更新环与回滚流程、离线/气隙交付、白名单计划、卸载净空清单与企业交付文档，再写安装器。**静默参数、退出码、日志留痕必须在测试机实测；仅管理员明确锁定的键在 UI 标明「由组织管理」且不可改；配置逐键降级不因陌生键白屏；管理员可禁用自动更新；托管策略优先仅适用于明确锁定的键，未锁定的用户显式设置应用不得覆盖；运行时与许可的离线路径单独设计；白名单按实测提前提交；卸载净空且不误删用户数据。** 当前若无企业客户，把理由与触发重新评估的条件写进立项包并随版本复审（主大纲五档暂缓项）。实现后给出安装/升级/回滚/卸载演练记录，并列出未测 MDM 平台。所有包名、参数、策略键由当前项目与企业客户决定。

## 五档定位

| 档位 | 本方案承担 |
|---|---|
| 一档 | 是否存在企业分发需求的决策与暂缓记录 |
| 二档 | 包格式、静默安装、安装范围、基础托管键 |
| 三档 | 策略仲裁、更新环、日志与诊断可配置性 |
| 四档 | 白名单提前量、卸载净空演练、DPA/子处理者文档 |
| 五档 | 按主大纲原暂缓项：首个企业客户出现前可暂缓，保留理由与触发条件 |

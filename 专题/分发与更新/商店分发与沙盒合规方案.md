# 商店分发与沙盒合规方案：通用规划方案

## 这份方案是做什么的

来源：Mac App Store 提审清单（强制 App Sandbox、entitlements 逐项理由、Hardened Runtime、用户选择文件的读写权限、禁止自带更新/授权码/安装器、主窗口可重新打开、截图规格与审核信息）、主大纲四档「Windows MSIX 打包」「签名打包与更新分发技术方案」的商店分支，以及企业部署清单里的 PKG/MSI 分发。

母法方案：《签名打包与更新分发技术方案》（签名、公证、包格式、回滚）、《默认安装目录规划方案》（沙盒下目录契约变化）、《产品身份单一源方案》（Bundle ID / 桌面项）、《授权与许可方案》（商店内购与许可模型冲突）、《应用内更新体验方案》（商店禁止自带更新）、《企业部署与托管配置方案》（PKG/MSI）、《遥测与隐私合规方案》（隐私清单与数据声明）。

它管**「走商店渠道时，哪些架构决策会被审核规则反过来推翻」**。这些约束是外生的、不可协商的，且往往影响架构（沙盒下的文件访问、更新机制、许可模型），因此必须在立项期决策，不能等打包前才发现要改。

不预设：是否上商店、上架哪个商店、是否内购、沙盒权限清单。所有审核规则以当期官方文档为准，未核实的标**待验证**。

## 开始写代码前，先让 AI 回答这些问题

1. 是否走商店分发（Mac App Store / Microsoft Store / 其他）？还是仅官网直发？两者是否并行？
2. 若并行，商店版与直发版的**功能差异清单**是什么（更新、许可、诊断、插件、外部协议）？由什么构建 tag 或配置区分（→《生产构建安全基线方案》）？
3. macOS：是否启用 App Sandbox？每个 entitlement 的用途与必要性理由是什么？用户选择文件的读写权限如何申请（→《默认安装目录规划方案》）？
4. Hardened Runtime 与公证的签名命令、凭据配置是否可重复执行（→《签名打包与更新分发技术方案》）？
5. 商店规则禁止自带更新/安装器/授权码：现有更新机制、许可激活、插件下载路径如何改（→《应用内更新体验方案》《授权与许可方案》《插件扩展方案》）？
6. 主窗口关闭后能否重新打开（无托盘/Dock 常驻时）？单实例与唤回路径是否仍成立（→《单实例与快速启动方案》《窗口与多窗口技术方案》）？
7. 数据目录：沙盒容器路径与直发版的 XDG/注册表路径不同，迁移、备份、导出、卸载行为如何统一（→《默认安装目录规划方案》《数据可携带与彻底删除方案》）？
8. 权限申请时机、隐私清单/数据声明、屏幕录制/摄像头/通知等 TCC 权限与商店审核说明是否一致（→《系统能力与平台集成技术方案》《遥测与隐私合规方案》）？
9. 内购/订阅：是否使用商店的支付与收据校验？与自有许可模型冲突时谁优先（→《授权与许可方案》）？
10. 网络与离线：沙盒的网络 entitlement、企业代理/自定义 CA、离线功能预期（→《网络与离线弹性技术方案》《生产构建安全基线方案》）？
11. 审核材料：截图规格（尺寸、无 alpha）、名称/副标题的商标规则、每个平台的审核信息、演示账号、特殊权限说明由谁准备（→《用户文档与上手支持方案》）？
12. 首次运行：用**全新用户账户、无配置无文件**跑一遍，沙盒下是否仍能完成核心旅程？
13. 审核被拒后的回滚：能否快速切回官网直发版而不影响用户数据？

交付给 AI 的设计结果应包含：渠道决策、版本差异清单、沙盒 entitlement 表、签名与公证流程、功能差异改造、目录迁移、审核材料清单、被拒回滚路径。

## 核心纪律

### 一、渠道决策影响架构，必须前置

| 约束 | 影响面 | 相关专题 |
|---|---|---|
| 强制沙盒 | 文件 I/O、目录、外部进程、协议注册 | 《默认安装目录规划方案》《外部链接与协议回调安全方案》 |
| 禁止自带更新 | 更新机制与用户提示 | 《应用内更新体验方案》《签名打包与更新分发技术方案》 |
| 禁止自带授权码/安装器 | 许可激活与试用 | 《授权与许可方案》 |
| 用户选择文件权限 | 导入/导出/备份路径 | 《数据可携带与彻底删除方案》 |
| 商店内购与收据 | 付费模型 | 《授权与许可方案》《客户端与服务端API契约方案》 |
| 主窗口可重新打开 | 生命周期与唤回 | 《窗口与多窗口技术方案》《托盘技术方案》 |

**「先按官网直发做，上架时再改」通常会返工**：沙盒与禁止自带更新是架构级约束，不是打包脚本参数。

### 二、macOS 沙盒与 entitlement 逐项有理由

- 每个 entitlement 登记：键名、用途、必要性、拒绝时降级路径、审核说明；**没有理由的宽权限是审核被拒的高频原因**。
- 文件访问走用户选择文件的读写权限（打开/保存对话框），不能假设能读任意用户目录；路径来自 OS 传入，属于不受信输入（→《外部链接与协议回调安全方案》《输入数据验证方案》）。
- App Group 用于主应用与 helper/扩展共享数据；helper 的签名与 Bundle ID 一致性由身份单源校验（→《产品身份单一源方案》）。
- Hardened Runtime + 签名 + 公证流程从零演练一次，凭据配置可重复执行（→《签名打包与更新分发技术方案》）。
- 沙盒容器路径与直发版路径不同：**迁移逻辑要在立项期写成一条路径决策**，不能上架后才发现旧用户数据读不到（→《应用状态与持久化技术方案》）。

### 三、两版并存：差异清单由构建门守住

| 项 | 官网直发版 | 商店版 |
|---|---|---|
| 更新 | 应用内自更新 | 商店更新 |
| 许可 | 自有许可/离线激活 | 商店内购/收据 |
| 诊断上报 | 按同意策略 | 按商店隐私声明 |
| 插件/外部扩展 | 可下载 | 需随包或禁用（→《插件扩展方案》） |
| 协议注册 | 自定义协议 | 按审核规则 |

- 差异由**构建 tag / 配置的单一入口**产生，并有产物能力探测门（→《生产构建安全基线方案》《CI矩阵与质量门禁方案》）。
- 两版共用数据格式与导出契约，用户能在两版之间迁移数据（→《数据可携带与彻底删除方案》）。
- 版本号、身份、符号文件在两版分别归档，避免崩溃堆栈对不上构建（→《版本号方案》《崩溃上报与符号还原方案》）。

### 四、审核材料与被拒回滚

- 材料清单：截图规格、名称/副标题商标规则、逐平台审核信息、演示账号、权限用途说明、隐私清单；由明确 owner 维护（→《用户文档与上手支持方案》）。
- 首次运行用全新账户验证：无配置、无文件、权限未授予时核心旅程可完成。
- 审核被拒要能在不改数据格式的前提下回退到直发版；两版的发布流水线与回滚路径分别演练（→《发布交付流水线方案》）。
- 审核规则会变：每次提审前复核当期官方文档，未核实的标待验证，不照抄上一次的经验。

## 常见根因表

| 表面现象 | 常见根因 | 开始实现前的预防 |
|---|---|---|
| MAS 审核因缺沙盒被拒 | 立项时未把沙盒当架构约束 | 渠道决策前置 + entitlement 表 |
| 因自带更新器被拒 | 直发版更新机制直接搬进商店版 | 两版差异清单 + 构建门 |
| 上架后旧用户数据读不到 | 沙盒容器路径与直发版不同 | 目录迁移决策前置 |
| 权限申请被要求补说明 | entitlement 无用途理由 | 逐项理由 + 拒绝降级路径 |
| 截图/副标题被拒 | 商标与规格规则未核对 | 审核材料清单 + 提审前复核 |
| 主窗口关了打不开 | 依赖托盘/Dock 常驻 | 重新打开路径（→《窗口与多窗口技术方案》） |
| 两版崩溃堆栈对不上 | 版本/符号文件未分别归档 | 按构建哈希归档（→《崩溃上报与符号还原方案》） |
| 全新账户首次运行走不通 | 只在开发者机器上验 | 全新账户冒烟 |

## 先设计测试矩阵，再开始实现

| 维度 | 要覆盖 |
|---|---|
| 沙盒 | 每项 entitlement 允许/拒绝、用户选择文件读写、App Group helper、网络权限 |
| 差异 | 两版功能差异逐项断言；产物能力探测门故意失败一次 |
| 目录 | 直发→商店迁移、导出回环、卸载后数据行为 |
| 首次运行 | 全新账户、无配置无文件、权限未授予的核心旅程 |
| 签名 | Hardened Runtime + 公证从零演练、凭据重复执行 |
| 审核 | 材料清单逐项核对、提审前当期规则复核 |
| 回滚 | 被拒后切回直发版且用户数据不受影响 |

## 给 AI 的实施约束模板

> 先给出渠道决策、两版功能差异清单、macOS entitlement 表（用途/必要性/拒绝降级/审核说明）、签名与公证流程、沙盒目录迁移策略、审核材料清单与被拒回滚路径，再写打包配置。**商店约束是架构级：强制沙盒、禁止自带更新/安装器/授权码、用户选择文件权限，必须在立项期决策；每个 entitlement 写清理由；两版差异由构建 tag 单一入口产生并有产物能力探测门；两版共用数据格式与导出契约；沙盒容器路径与直发版路径的迁移先写成决策；首次运行用全新账户验证；审核材料由明确 owner 维护并在每次提审前复核当期官方文档。** 查不到依据的规则写「待验证」，不得照抄上一次经验。实现后给出沙盒、差异、迁移、首次运行、回滚的可观察测试，并列出未实测平台。所有渠道、权限、内购模型由当前项目与法务决定。

## 五档定位

| 档位 | 本方案承担 |
|---|---|
| 一档 | 是否上商店的渠道决策（决定架构，不回答不写文件 I/O） |
| 二档 | 沙盒 entitlement 表、签名公证流程、目录迁移、两版差异 |
| 三档 | 权限申请时机、隐私清单、审核材料 owner |
| 四档 | 全新账户冒烟、产物能力探测门、被拒回滚演练——缺项不得提审 |
| 五档 | 不上商店时可整体暂缓，但须写理由与触发条件（首个商店渠道需求出现时重评） |

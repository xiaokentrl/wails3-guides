# 默认安装目录规划：Wails3 + Go 专用方案

## 定位与硬性目标

母法方案：《签名打包与更新分发技术方案》。母法管「签名、打包、更新与回滚」；本方案管**文件住址**——程序、数据、缓存、日志在三大平台的唯一归属，以及安装根的解析规则。姊妹方案：《版本号方案》（版本号单源）、《发布交付流水线方案》（交付链操作序列——本方案的目录契约是其中「出包/安装」两步的输入）。

**硬性目标**：

1. 目录契约单源：全部路径由唯一模块按平台推导，代码中禁止出现硬编码路径字符串；
2. 分类集中：每类文件有且仅有一个归属目录，任何文件不得落在契约之外；
3. 只读程序区：安装目录在运行期只读——数据、缓存、日志一律不写入；
4. 卸载即净空：卸载器能按契约枚举并清除全部落地文件，无残留。

## 核心原则：分类集中，而非单目录混装

「全部资源集中存放」的正确实现是**每类文件一个唯一归属**，不是把所有东西塞进安装目录：

- macOS：写入 `.app` 包内会破坏代码签名，更新即失效；
- Windows：`Program Files` 受 ACL 保护，写数据撞权限；多用户共用安装目录时数据互相覆盖；
- Linux：写 `/opt` 违反 FHS（只读程序区），卸载不净。

**「乱扔文件」的黑名单**（每一条都是真实软件踩过的坑）：

| 反模式 | 危害 |
|---|---|
| `$HOME/.软件名` 裸点目录 | 家目录污染，用户最反感的形式 |
| 数据写在 exe 旁边 | Windows ACL 拒写 / 多用户互踩 / 签名失效 |
| 配置散落注册表各处不集中 | 无法备份、无法卸载净空 |
| 缓存写进数据区 | 备份膨胀、数据目录不可预期 |
| 日志写进程序目录 | 磁盘涨满且更新时被连带清除 |
| 硬编码 `C:\`、`D:\`、`/usr/share` | 换机器即坏 |

## 目录契约：六类文件 × 三平台

约定 `<AppName>` = 安装器/包名（如 `软件名`），`<BundleID>` = 反向域名（如 `com.company.appname`），`<Company>` = 公司名。**BundleID 是 macOS 的目录命名权威**（非中文软件名）。

**主根（单根集中）**：用户数据 / 配置 / 日志三区同根——用户备份、卸载、排障只看一个目录。**唯一例外是缓存**：系统清理工具（Windows 磁盘清理、macOS 存储管理、Linux ~/.cache 清理）只认平台缓存目录，缓存并入主根会让这些工具全部失效，故单列。

约定 `<AppName>` = 安装名，`<BundleID>` = 反向域名，`<Company>` = 公司名。**BundleID 是 macOS 的目录命名权威**（非中文软件名）。

| 类别 | Linux | Windows | macOS |
|---|---|---|---|
| **主根** | `~/.local/share/<app>/` | `%LOCALAPPDATA%\<Company>\<AppName>\` | `~/Library/Application Support/<BundleID>/` |
| └ 配置 | `<主根>/config/` | `<主根>/config/` | `<主根>/config/` |
| └ 用户数据 | `<主根>/data/` | `<主根>/data/` | `<主根>/data/` |
| └ 日志 | `<主根>/logs/` | `<主根>/logs/` | `<主根>/logs/` |
| **缓存（唯一外置）** | `~/.cache/<app>/` | `<主根>/Cache/`（LOCALAPPDATA 不漫游，可内联） | `~/Library/Caches/<BundleID>/` |
| **程序区**（只读） | `/opt/<AppName>/` 或 `~/.local/opt/<AppName>/` | 安装根（见解析链） | `/Applications/<AppName>.app` |
| **可执行入口** | `/usr/local/bin/<app>` 或 `~/.local/bin/<app>` 符号链接 | 安装根内 exe + 快捷方式 | `.app` 内置 |
| **临时文件** | `$XDG_RUNTIME_DIR/<app>/` 或 `/tmp` | `%TEMP%\<AppName>\` | `$TMPDIR` |
| **共享/机数据** | `/var/lib/<app>/`（仅系统服务） | `%ProgramData%\...`（仅 per-machine 需要时） | `~/Library/Group Containers/<GroupID>/`（仅套件共享） |

> per-user 安装（Linux/Windows 免提权档）只是程序区换位置，数据主根不变。

**旧四分契约（XDG 原教旨：share/config/cache/state 各一处）保留为备选档**——仅当产品明确要进 Linux 发行版官方仓库（打包者要求遵守 FHS/XDG 原教旨）时切换，桌面自分发产品默认用上表单根契约。

> 上表即**目录契约**。每一格的完整路径有且仅有一个；全部由单源模块推导（见下），契约之外的任何写操作都是缺陷。

## 三平台安装根解析

### Linux：`/opt/<AppName>/`（产品默认，符合 FHS）

- 多用户自包含安装：程序文件全部进 `/opt/<AppName>/`（FHS 3.0 §3.13：第三方自包含软件的指定位置）；`/usr/local/bin/<app>` 放符号链接供命令行调用；
- 可变数据：服务端场景才用 `/var/opt/<AppName>/`，桌面应用一律走用户 XDG 目录；
- **per-user 安装**（无 sudo）：整棵树迁到 `~/.local/opt/<AppName>/` + `~/.local/bin` 链接；
- 卸载：删 `/opt/<AppName>/` 与符号链接即净（用户数据在契约目录，由卸载器按用户确认清除）。

### Windows：安装根解析链（安装器执行，结果持久化）

产品要求「默认安装到 `D:\软件名`」——正确编码方式是**默认优先级解析链**，而非硬编码盘符（无 D 盘的机器即坏）：

```
安装根解析链（安装器逐步求值）：
1. **用户指定目录：绝对遵从**——校验（可写、空间、文件系统）通过即用；**绝不静默重定向**。校验失败时给出明确原因与修复建议，由用户改选，安装器不替用户做主
   - 仅有的拒绝条件：指向系统保护区（如 C:\Windows 内部）或非法路径——报错并说明，仍由用户改选
   - 空间不足/权限不足 → 明确报错让用户处理，而非偷偷换地方
2. 用户未指定时的产品默认：D:\软件名（条件：D: 存在 ∧ NTFS ∧ 剩余空间 ≥ 500MB）；不满足则回退 %LocalAppData%\Programs\软件名（免提权）；企业 per-machine 场景 %ProgramFiles%\软件名（需提权）
3. 用户选择持久化（注册表 InstallPath + 安装器记忆），下次升级/更新默认沿用
```

- 解析结果持久化：注册表 `HKLM`（per-machine）或 `HKCU`（per-user）`Software\<Company>\<AppName>` 的 `InstallPath` 值 + 卸载信息（UninstallString / DisplayVersion / DisplayIcon）；
- **运行期永不重算安装根**——安装器写、运行时读（单源注入，与《版本号方案》的版本单源同构）；
- 更新器写安装目录时以安装根 ACL 为准：per-user 安装无需提权，per-machine 更新需提权或使用更新服务。

## 写入最小化：注册表与系统深处的红线

原则：**能写文件的不写注册表，能写自己目录的不碰系统目录**。注册表白名单制——白名单之外一律禁止，且总数可数。

| 位置 | 允许？ | 说明 |
|---|---|---|
| `HKCU\Software\<Company>\<AppName>`（含 Uninstall 子键） | ✅ 唯一常驻键 | InstallPath、DisplayVersion、UninstallString——「控制面板卸载列表」是系统强制要求，无法避免 |
| `HKLM\Software\<Company>\<AppName>` | ✅ 仅 per-machine 安装 | 同上，需提权时 |
| `HKCU\...\Run` 自启动 | ⚠️ 需显式同意 | 默认**不装**；设置页显式开关 + 明确标注「开机自启」 |
| 文件关联 / 右键菜单 / shell 扩展 | ⚠️ 需显式同意 | 默认不装；安装器单独勾选项 |
| 系统服务 / 驱动 / 浏览器插件 | ❌ 禁止 | 无此必要 |
| 其他任何注册表位置 | ❌ 禁止 | 违反即缺陷 |

配套纪律：

- **PATH 环境变量**：只改用户级（HKCU Environment），安装器文档化该行为，卸载还原；默认不加；
- **防火墙规则 / 计划任务**：创建即记录（清单见下），卸载反向清除；
- **per-user 优先**：能 `%LocalAppData%` 不 `HKLM`——免提权即免污染。

## 安装清单与目录结构可视化（所写即所录）

**所写即所录**：安装器触碰的每一个文件、每一个注册表值、每一个快捷方式，**创建时即记入清单**——卸载、修复、审计以清单为唯一依据，不靠事后扫描猜测。

1. **`manifest.json`**（写入安装根，机器可读）：全部落地文件的相对路径 + SHA256 + 用途标注（程序/文档/数据）+ 创建来源（安装器/更新器/运行期）；
2. **`目录结构.txt`**（人类可读版）：树形缩进 + 每个目录的用途注释，安装完成即生成；
3. **安装完成页**：渲染目录树 + 「打开安装目录」「打开数据目录」按钮；
4. **运行期可查**：设置 → 「存储位置」页（各目录路径 + 打开按钮）；CLI `<app> paths` 输出全部位置；
5. **卸载 = 反向执行清单**：按 manifest 删文件 → 删快捷方式/注册表值 → 运行期新增文件（不在清单）按用户选择处理；
6. **完整性**：每次启动校验 manifest 哈希（抽查）——被篡改/损坏可在设置页一键修复。

## 数据目录自定义（聚合模式，高级选项）

- **默认（契约模式）**：主根三区（config/data/logs）+ 平台缓存目录外置——OS 清理工具友好；
- **聚合模式（安装器「数据目录」高级选项）**：用户指定目录后，**四区全部收进一个目录**——

```
<用户指定的数据目录>/<AppName>/
├── config/    ← 配置
├── data/      ← 用户数据
├── cache/     ← 缓存（聚合后由应用自管）
└── logs/      ← 日志
```

- 用户备份/迁移/卸载**只看这一个目录**——「全部资源集中存放」的完全体；
- paths 模块读取用户覆盖并持久化（安装器写入 InstallPath 同级的 `DataRoot`），运行期永不重算；
- **配套义务：缓存自管理**。聚合后 OS 清理工具不再管理缓存，应用必须自带上限策略（LRU / 容量上限，默认 500MB，设置页可见可清）——否则缓存无界增长就是另一种「乱拉屎」；
- **两层控制权分离不变**：程序区绝对遵从用户指定；数据区默认契约、聚合模式可选——控制权给用户，机制不破坏。

### macOS：`/Applications/<AppName>.app`（唯一正确答案）

- 安装 = 把 `.app` 拖入 `/Applications`（DMG 内放 Applications 快捷方式引导），**没有「选择安装目录」的惯例**——用户硬要放别处，Gatekeeper 隔离属性与Launchpad 体验都会劣化，方案明确不做；
- 数据全走 `~/Library` 家族（见契约表），命名用 `<BundleID>`（反向域名），**绝不用中文名**（工具链对非 ASCII 目录名的兼容性不可控）；
- **红线：运行期对 `.app` 包内零写入**——任何写入都会破坏代码签名，导致更新后失效或 Gatekeeper 拒启；
- 沙盒化（未来上架 App Store 时）：目录自动迁移到 `~/Library/Containers/<BundleID>/`，由 `FileManager` 标准 API 解析——paths 模块预留沙盒分支即可，无需改契约。

## 单源实现：paths.go（唯一路径推导模块）

```go
// paths/paths.go —— 全库唯一允许出现平台路径逻辑的文件
package paths

type Layout struct {
    AppRoot    string // 主根：config/data/logs 三区的父目录（单源）
    ConfigDir  string // <AppRoot>/config
    DataDir    string // <AppRoot>/data
    LogDir     string // <AppRoot>/logs
    CacheDir   string // 平台缓存目录（唯一外置：OS 清理工具契约）
    InstallDir string // 程序区（Windows 读注册表 InstallPath；macOS 推导 .app；Linux /opt 或 ~/.local/opt）
    TempDir    string // 临时
}

func Resolve(appName, bundleID, company string, dataRootOverride string) Layout {
    // 聚合模式（dataRootOverride 非空）：四区全部收进 <override>/<app>/
    //   config/ data/ logs/ cache/ —— 缓存自管理（应用内置 LRU/容量上限，设置页可见可清）
    // 契约模式（override 为空）：
    //   主根：Linux ~/.local/share/<app> ｜ Windows %LOCALAPPDATA%\<Company>\<App> ｜ macOS ~/Library/Application Support/<BundleID>
    //   缓存：Linux ~/.cache/<app> ｜ Windows <AppRoot>/Cache ｜ macOS ~/Library/Caches/<BundleID>
    // InstallDir：Windows 读注册表 InstallPath（回退 os.Executable 目录）；macOS 由 main bundle 推导；Linux /opt 或 ~/.local/opt
}

// Windows 专属：安装器写入的 InstallPath
func windowsInstallRoot(company, app string) string { /* 读 HKLM/HKCU InstallPath，缺省回退 os.Executable 目录 */ }
```

**纪律**：

1. 全库引用 `paths.Resolve()` 的返回值，`grep` 断言：除 paths.go 与安装器外，`*.go` 中不得出现 `Program Files`、`AppData`、`/opt/`、`Application Support` 字面量；
2. 每个目录首次使用前 `MkdirAll`，权限 Linux `0o755`、数据文件 `0o600`；config/data/logs 三区必须同根；**聚合模式下缓存也在主根内**（OS 清理工具不覆盖 → 应用必须自带缓存上限清理，默认 500MB LRU，设置页可见可清）；
3. 临时文件用完即删，退出时兜底清理。

## 更新与卸载的目录契约义务

- **更新**（→ 母法）：只替换程序区；数据/配置结构变更走迁移（版本号驱动，向后兼容一档）；更新器对程序区的写入用安装器同等 ACL；
- **卸载**：按契约反向枚举——程序区必删；用户数据/配置**默认保留**（用户可能重装），提供「同时删除个人数据」显式选项；缓存/日志/临时必删；
- **迁移**：目录布局变更是版本化事件——旧布局检测 → 原子迁移 → 旧目录留 `MIGRATED` 标记（一个空文件即可），失败可回退。

## AI 约束模板

> 实现任何文件读写时，必须从 `paths.Resolve()` 获取目录，禁止硬编码路径或在 exe 目录旁创建文件；新文件类型出现时先登记进目录契约表再实现；Linux 遵守 FHS/XDG，Windows 区分 per-machine/per-user 并持久化 InstallPath，macOS 数据走 `~/Library` 家族、命名用 BundleID、对 `.app` 包内零写入；**注册表白名单制：除卸载信息键外禁写注册表，自启动/文件关联/shell 扩展默认不装、需显式同意并记录**；**安装器遵守「所写即所录」：每个触碰的文件/键/快捷方式创建时记入 manifest，卸载反向执行**；**用户指定安装目录绝对遵从，校验失败明确报错不静默重定向**；实现后运行路径单源 grep 断言、注册表白名单扫描与三平台矩阵，任何契约外写入视为缺陷。

## 五档定位

- **一档**：目录契约表 + paths.go 单源模块 + 解析链规则，作为安装器与运行期的强制约定；
- **二档**：三平台安装器落地契约（NSIS/DMG/deb 或 AppImage），卸载器按契约净空；
- **持续**：新文件类型先登记契约再实现；契约外写入进 CI 断言。

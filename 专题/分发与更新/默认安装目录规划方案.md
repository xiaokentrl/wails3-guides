# 默认安装目录规划：Wails3 + Go 专用方案

## 定位与硬性目标

母法方案：《签名打包与更新分发技术方案》。母法管「签名、打包、更新与回滚」；本方案管**文件住址**——程序、数据、缓存、日志在三大平台的唯一归属，以及安装根的解析规则。姊妹方案：《版本号方案》（版本号单源）、《发布交付流水线方案》（交付链操作序列——本方案的目录契约是其中「出包/安装」两步的输入）。

**硬性目标**：

1. 目录契约单源：全部路径由唯一模块按平台推导，代码中禁止出现硬编码路径字符串；
2. 分类集中：每类文件有且仅有一个归属目录，任何文件不得落在契约之外；
3. 只读程序区：安装目录在运行期只读——数据、缓存、日志一律不写入；
4. 卸载即净空：卸载器能按契约枚举并清除全部落地文件，无残留。

## 核心原则：分类集中，而非单目录混装

「全部资源集中存放」的正确实现是**每类文件一个唯一归属**，不是把所有东西塞进安装目录：

- macOS：写入 `.app` 包内会破坏代码签名，更新即失效；
- Windows：`Program Files` 受 ACL 保护，写数据撞权限；多用户共用安装目录时数据互相覆盖；
- Linux：写 `/opt` 违反 FHS（只读程序区），卸载不净。

**「乱扔文件」的黑名单**（每一条都是真实软件踩过的坑）：

| 反模式 | 危害 |
|---|---|
| `$HOME/.软件名` 裸点目录 | 家目录污染，用户最反感的形式 |
| 数据写在 exe 旁边 | Windows ACL 拒写 / 多用户互踩 / 签名失效 |
| 配置散落注册表各处不集中 | 无法备份、无法卸载净空 |
| 缓存写进数据区 | 备份膨胀、数据目录不可预期 |
| 日志写进程序目录 | 磁盘涨满且更新时被连带清除 |
| 硬编码 `C:\`、`D:\`、`/usr/share` | 换机器即坏 |

## 目录契约：六类文件 × 三平台

约定 `<AppName>` = 安装器/包名（如 `软件名`），`<BundleID>` = 反向域名（如 `com.company.appname`），`<Company>` = 公司名。**BundleID 是 macOS 的目录命名权威**（非中文软件名）。

| 类别 | Linux（多用户安装） | Linux（per-user 安装） | Windows | macOS |
|---|---|---|---|---|
| **程序区**（只读） | `/opt/<AppName>/` | `~/.local/opt/<AppName>/` | 安装根（见解析链） | `/Applications/<AppName>.app` |
| **可执行入口** | `/usr/local/bin/<app>` → 符号链接 | `~/.local/bin/<app>` → 符号链接 | 安装根内 exe + 开始菜单/桌面快捷方式 | `.app` 内置 + 可选 `ln -s` 到 `/usr/local/bin` |
| **用户数据** | `~/.local/share/<app>/` | 同左 | `%APPDATA%\<Company>\<AppName>\` | `~/Library/Application Support/<BundleID>/` |
| **配置** | `~/.config/<app>/` | 同左 | 与用户数据同根（`config.json` 等） | 同上（或 `Preferences/<BundleID>.plist`） |
| **缓存** | `~/.cache/<app>/` | 同左 | `%LOCALAPPDATA%\<Company>\<AppName>\Cache\` | `~/Library/Caches/<BundleID>/` |
| **日志** | `~/.local/state/<app>/log/` | 同左 | `%LOCALAPPDATA%\...\Logs\` | `~/Library/Logs/<BundleID>/` |
| **临时文件** | `$XDG_RUNTIME_DIR/<app>/` 或 `/tmp` | 同左 | `%TEMP%\<AppName>\` | `$TMPDIR` |
| **共享/机数据** | `/var/lib/<app>/`（仅系统服务时） | — | `%ProgramData%\<Company>\<AppName>\`（仅 per-machine 需要时） | `~/Library/Group Containers/<GroupID>/`（仅多 app 共享时） |

> 上表即**目录契约**。每一格的完整路径有且仅有一个；全部由单源模块推导（见下），契约之外的任何写操作都是缺陷。

## 三平台安装根解析

### Linux：`/opt/<AppName>/`（产品默认，符合 FHS）

- 多用户自包含安装：程序文件全部进 `/opt/<AppName>/`（FHS 3.0 §3.13：第三方自包含软件的指定位置）；`/usr/local/bin/<app>` 放符号链接供命令行调用；
- 可变数据：服务端场景才用 `/var/opt/<AppName>/`，桌面应用一律走用户 XDG 目录；
- **per-user 安装**（无 sudo）：整棵树迁到 `~/.local/opt/<AppName>/` + `~/.local/bin` 链接；
- 卸载：删 `/opt/<AppName>/` 与符号链接即净（用户数据在契约目录，由卸载器按用户确认清除）。

### Windows：安装根解析链（安装器执行，结果持久化）

产品要求「默认安装到 `D:\软件名`」——正确编码方式是**默认优先级解析链**，而非硬编码盘符（无 D 盘的机器即坏）：

```
安装根解析链（安装器逐步求值，取第一个命中的）：
1. 安装器界面用户选择（最高优先级——用户改过的路径必须记住）
2. 产品默认：D:\软件名（条件：D: 存在 ∧ NTFS ∧ 剩余空间 ≥ 500MB）
3. 回退（免提权）：%LocalAppData%\Programs\软件名
4. 企业环境（per-machine，需提权）：%ProgramFiles%\软件名
```

- 解析结果持久化：注册表 `HKLM`（per-machine）或 `HKCU`（per-user）`Software\<Company>\<AppName>` 的 `InstallPath` 值 + 卸载信息（UninstallString / DisplayVersion / DisplayIcon）；
- **运行期永不重算安装根**——安装器写、运行时读（单源注入，与《版本号方案》的版本单源同构）；
- 更新器写安装目录时以安装根 ACL 为准：per-user 安装无需提权，per-machine 更新需提权或使用更新服务。

### macOS：`/Applications/<AppName>.app`（唯一正确答案）

- 安装 = 把 `.app` 拖入 `/Applications`（DMG 内放 Applications 快捷方式引导），**没有「选择安装目录」的惯例**——用户硬要放别处，Gatekeeper 隔离属性与Launchpad 体验都会劣化，方案明确不做；
- 数据全走 `~/Library` 家族（见契约表），命名用 `<BundleID>`（反向域名），**绝不用中文名**（工具链对非 ASCII 目录名的兼容性不可控）；
- **红线：运行期对 `.app` 包内零写入**——任何写入都会破坏代码签名，导致更新后失效或 Gatekeeper 拒启；
- 沙盒化（未来上架 App Store 时）：目录自动迁移到 `~/Library/Containers/<BundleID>/`，由 `FileManager` 标准 API 解析——paths 模块预留沙盒分支即可，无需改契约。

**纪律**：

1. 全库引用 `paths.Resolve()` 的返回值，`grep` 断言：除 paths.go 与安装器外，`*.go` 中不得出现 `Program Files`、`AppData`、`/opt/`、`Application Support` 字面量；
2. 每个目录首次使用前 `MkdirAll`，权限 Linux `0o755`、数据文件 `0o600`；
3. 临时文件用完即删，退出时兜底清理。

## 更新与卸载的目录契约义务

- **更新**（→ 母法）：只替换程序区；数据/配置结构变更走迁移（版本号驱动，向后兼容一档）；更新器对程序区的写入用安装器同等 ACL；
- **卸载**：按契约反向枚举——程序区必删；用户数据/配置**默认保留**（用户可能重装），提供「同时删除个人数据」显式选项；缓存/日志/临时必删；
- **迁移**：目录布局变更是版本化事件——旧布局检测 → 原子迁移 → 旧目录留 `MIGRATED` 标记（一个空文件即可），失败可回退。

## AI 约束模板

> 实现任何文件读写时，必须从 `paths.Resolve()` 获取目录，禁止硬编码路径或在 exe 目录旁创建文件；新文件类型出现时先登记进目录契约表再实现；Linux 遵守 FHS/XDG，Windows 区分 per-machine/per-user 并持久化 InstallPath，macOS 数据走 `~/Library` 家族、命名用 BundleID、对 `.app` 包内零写入；卸载按契约反向枚举，用户数据默认保留。实现后运行路径单源 grep 断言与三平台矩阵，任何契约外写入视为缺陷。

## 五档定位

- **一档**：目录契约表 + paths.go 单源模块 + 解析链规则，作为安装器与运行期的强制约定；
- **二档**：三平台安装器落地契约（NSIS/DMG/deb 或 AppImage），卸载器按契约净空；
- **持续**：新文件类型先登记契约再实现；契约外写入进 CI 断言。

# 登录与权限：通用规划方案

## 这份方案是做什么的

应用接入账号的那一刻，「谁能做什么」变成两个独立问题：**认证**（你是谁——登录与会话生命周期）和**授权**（你能做什么——应用内权限模型）。本方案把两者放在一起规划，避免做了一半才发现：token 过期时界面在乱飞、权限只在 UI 上隐藏（API 直调全绕过）、登出后数据残留、多窗口一个登录一个没登。

**与相邻方案的分工**：
- 信任边界、凭据存储、OAuth 回调拓扑、IPC 鉴权 →《安全边界与权限技术方案》（本方案的登录**机制**引用它，不重复）；
- OS 级权限（麦克风、文件、通知）→《系统能力与平台集成技术方案》——与本方案的应用内权限**完全无关**，不要混谈；
- 登出 / 换号的数据边界 →《多端数据同步方案》；会话与凭据的持久化 →《应用状态与持久化技术方案》敏感类。

**硬性目标**：**会话是事实、权限判定住领域层、UI 只是投影**——绕过 UI 的任何路径（API 直调、CLI、同步）都过同一套权限检查；token 刷新并发安全；登出可审计地清理干净。

## 第一步：分档决策（两个维度独立选）

**认证档**：

| 档 | 模型 | 说明 |
|---|---|---|
| A0 | 无账号（纯本地） | 多数单机应用的正确选择；记入暂缓 |
| A1 | 可选云账号 | 本地功能完整 + 云同步/协作需登录（→ 多端方案） |
| A2 | 必须登录 | 账号即产品前提（订阅、团队服务） |

**授权档**：

| 档 | 模型 | 说明 |
|---|---|---|
| P0 | 单用户无权限 | 本地应用 |
| P1 | 简单角色 | owner / member 两级，权限枚举固定 |
| P2 | RBAC | 角色 → 权限 → 资源，权限清单可配置 |
| P3 | ABAC / 关系型 | 按属性、按关系动态判定（团队协作复杂场景） |

**决策规则**：逐能力选档，默认最低档；A0 + P0 时本方案只需记录暂缓。**授权档只升不降**——权限模型是对用户的承诺。

## 认证：会话生命周期纪律

- **会话是事实**：登录态、当前用户、角色住权威层（→ 状态方案敏感类：令牌永不进普通配置），前端持有的是投影。多窗口同一会话天然一致——因为只有一份。
- **token 刷新单飞**：并发请求遇到过期时，**全应用只有一个刷新在途**，其余等待结果——刷新风暴与「旧 token 覆盖新 token」是认证类第一 bug（单飞与《缓存一致性方案》《任务队列方案》同一形状）。
- **过期处理一条路**：刷新失败 → 全局进入「需重新登录」状态（一个事实变更，全部表面收敛），不散落各处各自处理 401。
- **登出可审计**：登出 = 吊销令牌 + 清理会话态 + 按《多端数据同步方案》的账号边界处理本地数据——清理清单成文，漏一项就是数据残留事故。
- **登录流程机制**（loopback / deep link / 设备码）→ 安全方案 OAuth 回调拓扑；验证码作为第二因子的全链路 →《验证码方案》；登录失败的反馈 → 操作反馈方案失败三件套。
- **离线与会话**：会话过期判定依赖服务器时间还是本地（→ 网络方案时钟）；离线时已过期的会话**明确降级**（只读或锁定），不假装仍在线。

## 授权：权限判定住领域层

- **权限模型单源**：权限清单（permission registry）集中定义；**每个命令声明所需权限**——与《菜单方案》命令注册表同源（命令带 `permission` 字段），UI、CLI、同步入口共用同一判定。
- **判定只住领域层**（→ 输入验证方案四层职责的授权版）：领域服务执行命令前检查权限——UI 隐藏只是体验优化，**不是授权**；绕过 UI 的路径照常被拦。
- **有云则服务端强制**：客户端权限判定只做体验，服务端对每个写操作重查（前端不可信 → 安全方案公理的授权推论）。
- **无权限操作的呈现**：三选一并登记进操作-反馈矩阵（→ 操作反馈方案）——**隐藏**（无关系的能力不出现，防噪音）/ **禁用 + 原因**（需要被看见的能力，如升级入口）/ **执行后报错**（仅兜底）。同类能力全应用同一选择。
- **权限变更即时生效**：角色/权限是事实，变更走统一落定层刷新全部表面——不要求重启。

## 测试矩阵

| 维度 | 要覆盖的情况 |
|---|---|
| 会话 | 过期瞬间有在途操作、并发触发刷新（单飞验证）、刷新失败全局收敛、多窗口会话一致 |
| 登出 | 清理清单逐项核验（令牌、会话态、缓存、本地数据按策略）、登出后 API 全被拒 |
| 授权 | 每条命令的权限判定：UI 路径、API 直调、CLI、同步下行四路全过领域检查 |
| 呈现 | 无权限能力按登记策略呈现；权限变更即时生效不重启 |
| 边界 | 离线 + 会话过期；账号切换（→ 多端方案矩阵） |
| 服务端 | 客户端判过、服务端拒绝（不可信推论验证） |

## 常见根因

| 表面现象 | 常见根因 | 开始实现前的预防 |
|---|---|---|
| 权限形同虚设 | 只在 UI 隐藏，领域层不查 | 判定住领域层 + 四路绕过测试 |
| token 刷新风暴 / 互踢 | 并发刷新无单飞 | 全局唯一刷新在途 |
| 登出后还能操作 / 数据残留 | 清理清单不全、令牌未吊销 | 清单成文 + 审计 |
| 两个窗口登录态不一样 | 会话存了多份 | 会话是事实，单源 |
| 401 各处各自处理 | 过期处理散落 | 全局收敛为一条路 |
| 权限改了要重启 | 权限态非事实、无失效 | 走统一落定层 |
| 离线时假装还在线 | 会话过期不判定降级 | 离线 + 会话组合用例 |
| 服务端裸奔 | 只信客户端判定 | 服务端强制写进纪律 |

## 给 AI 的实施约束模板

开始实现时，可要求 AI：

> 先给出认证档与授权档决策、权限清单与命令↔权限映射。会话与令牌按敏感类存储分离（永不进普通配置）；token 刷新全局单飞，过期处理全局收敛为一条「需重新登录」路径；登出按成文清单清理并吊销令牌。权限判定只住领域层，命令声明所需权限，UI/CLI/同步四条路径同源检查；有云则服务端对每个写操作强制重查；无权限能力按登记策略呈现（隐藏/禁用+原因/报错），权限变更走统一落定层即时生效。不得把 UI 可见性当授权；不得用本地墙钟判定会话过期（→ 网络方案时钟）。实现后跑测试矩阵（会话/登出/授权四路/边界/服务端），并明确列出未覆盖的组合。

方案确认后再改代码；认证方式与授权模型属产品决策，AI 给方案与推演，最终由用户裁决。

## 五档定位

- **一档**：A/P 两维分档决策（A0+P0 则整项记入暂缓）。
- **二档**：会话生命周期、权限清单与命令映射、领域层判定落地。
- **三 / 四档**：登出清理全量、服务端强制、权限变更即时性、离线组合全测（→ 主大纲五档暂缓清单）。

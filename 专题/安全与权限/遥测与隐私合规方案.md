# 遥测与隐私合规方案：通用规划方案

## 这份方案是做什么的

来源：GDPR 合规清单十项（DPA 与控制者/处理者关系、同意管理、DPIA、数据主体权利、隐私政策、留存与删除、子处理者、泄露通知、跨境传输、隐私设计与治理）、桌面崩溃上报的隐私实践、主大纲五档「遥测与隐私合规」暂缓项（原话：当前不采集遥测；开始采集或进入受监管市场时，采集清单、退出机制与法规声明需整体立项并过安全评审）。

母法方案：《本地敏感数据与密钥管理方案》（脱敏与按位置删除）、《日志与可诊断性技术方案》（日志契约）、《登录与权限方案》（账号与标识符）、《供应链安全与依赖治理方案》（供应商/SBOM）、《威胁建模与安全响应方案》（事件 runbook）、《操作反馈方案》（同意 UI）。

它管**「哪些数据离开用户设备、凭什么、留多久、怎么撤回、出事怎么报」**。不采集遥测也要有这份决策记录——**「不采集」是被记录的决策，不是没想过**。

不预设：是否采集、法规适用范围、供应商、留存期限、同意文案。所有具体值由产品与法务决定，法律结论不是工程判断。

## 开始写代码前，先让 AI 回答这些问题

1. 应用是否采集遥测/诊断/分析？逐类列出**采集字段、目的、法律依据、存储位置、接收方**；写不出来的字段不许上线。
2. 哪些处理是「运行所必需」（如检查签名更新），哪些是可选（细粒度使用遥测、增强诊断、采用率指标）？**能否一个「接受」按钮全包**？
3. 同意记录保存什么（用户/同意 ID、scope、版本、时间戳、UI 上下文、locale）？撤回后已有数据怎么处理？
4. 拒绝可选遥测时，更新路径是否仍然可用？支持团队少了哪些能力，是否已告知？
5.  Identifier 设计：用假名/聚合标识够不够？设备 ID、账号 ID、邮箱、支持工单键如何关联，能否在删除请求时按固定顺序检索？
6. 每个存储位置的留存期（运维日志、单设备诊断、发布历史、分析导出、备份与副本、支持附件）分别是多少？由什么自动任务执行删除？
7. 数据主体权利（访问、更正、删除、限制、可携带、反对）的受理、验证、搜索、决策、响应流程是什么？能否在截止日前跑完一次演练？
8. 隐私政策是否按**功能**而非模糊类别描述（应用运行/诊断/分析/账户与支持）？是否在应用内首次运行展示并可随时查看？
9. 何时需要 DPIA：受众定向发布、基于崩溃信号的自动回滚、扩展诊断采集，这些是否已在实施前评审？
10. 子处理者清单：更新服务、云/CDN、崩溃监控、分析、支持聊天、工单、邮件各接触什么数据？谁批准引入、何时复审？
11. 跨境传输：数据经过哪些区域、边缘节点、支持团队访问路径？技术保障（加密/最小化/区域控制/访问限制）与合同措施分别是什么？
12. 泄露通知：谁判定「安全事件 / 个人数据泄露」、谁启动倒计时、证据保全清单是什么（→《威胁建模与安全响应方案》）？
13. 自编译构建/无账号版本是否默认不发送任何数据？构建 tag 如何保证？

交付给 AI 的设计结果应包含：数据流清单、同意分层与回执、留存与删除矩阵、DSAR 工作流、隐私政策、DPIA 结论、子处理者清单、跨境传输说明、事件 runbook、退出机制。

## 核心纪律

### 一、数据流清单：不能画在白板上的数据流就是没设计完

| 数据类别 | 字段 | 目的 | 法律依据 | 存储位置 | 接收方 | 留存 | 删除触发 |
|---|---|---|---|---|---|---|---|
| 必要更新 | 版本、签名校验结果 | 交付签名更新 | 按法务结论 | 更新服务 | 更新服务 | 登记 | 自动化任务 |
| 可选诊断 | 错误码、堆栈（脱敏）、环境摘要 | 排障 | 同意 | 崩溃监控 | 子处理者 | 最短 | 工单关闭/期满 |
| 可选分析 | 聚合采用率、版本分布 | 产品决策 | 同意 | 分析平台 | 子处理者 | 登记 | 聚合后删原始 |
| 账户与支持 | 联系方式、工单、附件 | 支持 | 按法务结论 | 支持平台 | 子处理者 | 登记 | 请求/期满 |

**「我们只发技术信息」不是字段清单**。任何新增 SDK、改遥测字段、改留存策略、引入受众定向，都视作数据流变更，重新过评审并更新文书。

### 二、同意：必需与可选分开，且可撤回

- 分层询问：必要更新交付 / 可选诊断 / 可选分析各自独立，捆绑在一个「接受」里既过不了监管也过不了企业审查。
- 同意记录包含：同意 ID、scope、版本、时间戳、看到的文案版本、应用版本、locale；撤回后停止采集并按策略删除已有可识别数据。
- 撤回路径必须容易找到（设置内常驻入口），不需要重装或联系支持（→《操作反馈方案》《弹窗按钮文案方案》）。
- 拒绝可选遥测时**核心功能与更新仍可用**；支持能力下降要如实告知，不能暗中降质逼用户同意。
- 自编译/无账号构建默认零上报，且由构建 tag 与产物探测门证明（→《生产构建安全基线方案》）。

### 三、脱敏在存储前，删除按位置

- 脱敏白名单（而非黑名单）定义允许字段；在**写入日志/上传前**过滤 token、邮箱、自由文本、文件路径、设备密钥、用户内容。后处理只是第二道防线（→《本地敏感数据与密钥管理方案》）。
- 崩溃堆栈、支持导出、诊断包、桌面日志都可能含本地用户名或完整路径，逐项核对（→《崩溃上报与符号还原方案》《日志与可诊断性技术方案》）。
- 留存按**存储位置**分配策略，不按「数据类型」笼统写；备份、冷存储、临时工程导出、支持附件各有 owner 与到期任务。
- 「自动化就是政策」：靠支持工程师记得删共享盘里的导出包，一定会漏。例外用带有效期的工单标记，不发邮件提醒就永远保留。
- 删除请求要覆盖所有副本，且留下「删了什么、保留了什么、为什么」的审计记录；硬件/介质销毁流程同理。

### 四、DSAR、政策与治理

| 环节 | 要求 |
|---|---|
| 受理 | 统一隐私请求渠道，避免散落在多个收件箱 |
| 验证 | 按风险匹配强度，用侵入性最小但仍能确认的方式 |
| 搜索 | 按固定顺序查询系统映射图里的每个系统（账户、更新记录、诊断、本地产物、客服） |
| 决策 | 区分可擦除/可导出与因法律、安全、计费必须保留 |
| 响应 | 通俗语言说明结果与原因，留审计日志 |
| 政策 | 按功能描述处理流程；应用内首次运行展示、随时可查；多语言与产品同步（→《多语言实现方案》） |
| DPIA | 实施前记录假设、缓解措施、**选择不收集什么**、残余风险 |
| 子处理者 | 单一清单 + 负责人；架构一变就重评；客户可索取 |
| 治理 | 产品描述功能、工程记录数据流、安全检查访问/留存、法务确认依据与披露；隐私审查进 PR 模板与发布审批 |

**最早的信号常来自支持或客户成功，不是安全团队**：上报路径要写进支持手册，否则事实还躺在聊天里时倒计时已经在走。

## 常见根因表

| 表面现象 | 常见根因 | 开始实现前的预防 |
|---|---|---|
| 客户安全问卷发来没人答得出 | 数据流未成文、DPA 与工程对不上 | 数据流清单 + DPA 当工程产物维护 |
| 一个「接受」按钮全包 | 必需与可选未分层 | 分层同意 + 回执 + 撤回入口 |
| 撤回同意后仍在上传 | 同意状态只在 UI，未进执行点 | 执行点统一校验同意 scope + 产物探测 |
| 崩溃报告带用户文件名 | 黑名单脱敏、后处理 | 字段白名单 + 写入前过滤 |
| 删除请求超期 | 无系统映射、靠人工查表 | 固定检索顺序 + 演练计时 |
| 日志留存无限期漂移 | 无按位置的到期任务 | 生命周期策略 + 带有效期例外标记 |
| 新增 SDK 后关系变了但文书没变 | 供应商引入未触发复审 | 子处理者清单 + 变更触发条件 |
| 「不采集」后来悄悄开始采集 | 没有决策记录 | 五档暂缓项写入立项包并随版本复审 |

## 先设计测试矩阵，再开始实现

| 维度 | 要覆盖 |
|---|---|
| 同意 | 必需/可选分别接受与拒绝、撤回、文案版本变更、不同 locale |
| 执行点 | 拒绝后抓包/产物探测断言零上报；自编译构建零上报 |
| 脱敏 | 字段白名单断言；故意塞入 token/路径/邮箱，日志与上传均无命中 |
| 留存 | 到期任务真实执行、例外标记到期失效、备份副本同步删除 |
| DSAR | 用真实场景拉取某用户全链路记录并计时；保留项有理由 |
| 事件 | 四类桌面泄露场景演练（支持 token、管理员账号、存储桶、分析导出） |
| 文书 | 隐私政策与产品逐行对照；子处理者清单与 SBOM/供应商一致 |
| 未验 | 未覆盖法规辖区、未演练场景明确列出 |

## 给 AI 的实施约束模板

> 先给出数据流清单（字段/目的/依据/位置/接收方/留存/删除触发）、必需与可选同意分层及回执、脱敏字段白名单、按存储位置的留存与删除矩阵、DSAR 工作流、隐私政策、DPIA 结论、子处理者清单、跨境传输说明与事件 runbook，再写采集代码。**默认不采集；必需与可选不得捆绑同意；拒绝可选遥测时核心功能与更新仍可用；脱敏在写入/上传前完成；留存按存储位置分配到自动化任务；删除请求覆盖所有副本并留审计；自编译构建默认零上报且由构建门证明。** 任何新增 SDK、改字段、改留存、改定向规则都触发文书复审。法律结论由法务给出，工程不得自行判定；「不采集」也要作为决策记录进立项包。实现后给出同意/撤回/脱敏/删除/演练的可观察测试，并列出未覆盖辖区。所有字段、期限、供应商由当前项目与法务决定。

## 五档定位

| 档位 | 本方案承担 |
|---|---|
| 一档 | 「是否采集」的决策与书面记录；不采集也要立项（五档暂缓项前置化） |
| 二档 | 数据流清单、同意分层、脱敏白名单、退出机制 |
| 三档 | 留存与删除自动化、DSAR 工作流、隐私政策应用内展示 |
| 四档 | DPIA、子处理者与 DPA、跨境传输、事件演练与残余风险签字——进入受监管市场前不得发布 |
| 五档 | 按主大纲原暂缓项：未采集遥测时可暂缓实现，但必须保留理由与触发条件，随版本评审重读 |

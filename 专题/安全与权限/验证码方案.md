# 验证码：全面工程化通用方案

## 这份方案是做什么的

验证码横跨两件事：**认证**（证明你是谁的第二因子）与**反滥用**（证明你不是机器/不是攻击者）。本方案把验证码当**全链路工程**规划——生成、存储、下发、校验、防爆破、降级、审计——而不是「接一个验证码 SDK」的 UI 问题。它同时管前端的输入组件纪律（PinInput、倒计时）。

**与相邻方案的分工**：登录流程与会话 →《登录与权限方案》；限流与暴露面原则、凭据存储 →《安全边界与权限技术方案》；OTP 输入的结构化校验 →《输入数据验证方案》；倒计时与重发反馈 →《操作反馈方案》《防抖与节流方案》；审计日志 →《日志与可诊断性技术方案》；无障碍底线 →《无障碍与辅助技术方案》。

**硬性目标**：
1. 验证码**答案永远不出现在前端**（生成与校验全在服务端）；
2. **三条限流线**（按账号 / 按设备 / 按 IP）在服务端强制——短信轰炸与爆破在结构上不可行；
3. 每种验证码都有**无障碍替代路径**（视障用户不会被锁死）；
4. 全链路审计可查（发送、校验、失败、锁定）。

## 第一步：威胁模型与类型选型

先回答「防的是谁」——不同威胁对应完全不同的验证码强度：

| 威胁 | 有效手段 | 无效手段 |
|---|---|---|
| 脚本批量注册/撞库 | 行为验证码（滑块/点选）、设备指纹、限流 | 简单图形码（OCR 已成熟） |
| 账号盗用（第二因子） | 短信/邮箱 OTP、TOTP、**WebAuthn/Passkey** | 图形码（证明的是「是人」，不是「是本人」） |
| 短信通道滥用（轰炸） | 三线限流、发送冷却、图形码前置 | 只按账号限流 |
| 中间人/钓鱼 | WebAuthn（域绑定） | 一切可转发的 OTP |

**类型矩阵**（逐场景选型并记录理由）：

| 类型 | 强度 | 成本 | 无障碍 | 备注 |
|---|---|---|---|---|
| 图形码 | 低 | 低 | **差**（必须配音频/免码替代） | 仅作限流前置 |
| 滑块/点选（行为式） | 中 | 中（第三方服务） | 中（第三方程度不一，**待验证**） | 防脚本主力 |
| 短信 OTP | 中 | **高**（按条计费） | 好 | 转发即失效于钓鱼 |
| 邮箱 OTP | 中 | 低 | 好 | 送达延迟 |
| TOTP（认证器） | 中高 | 低 | 好 | 离线可用，需处理时钟漂移 |
| WebAuthn / Passkey | 高 | 中 | 中（平台支持度差异） | 无钓鱼，**长期方向** |

## 全链路工程纪律（七环）

### 1. 生成
- 服务端生成；随机源用密码学安全随机（`crypto.getRandomValues` / 服务端 CSPRNG），不用 `Math.random`；
- 图形码**在服务端渲染成图**——前端 canvas 自绘 = 答案在响应里，等于没防；
- 字符集去除易混淆字符（0/O、1/l/I）。

### 2. 存储
- 服务端只存 **hash**（同密码对待），不存明文；
- 绑定发放时的会话/设备上下文——换会话即失效，防跨会话重放；
- **一次性**：校验成功即消费；尝试次数独立计数（默认 3 次）。

### 3. 下发
- **三条限流线全部服务端强制**：按账号（N 条/天）、按设备指纹、按 IP——短信轰炸攻击刷的是你的账单；
- **重发冷却**：60s 倒计时（前端展示态，服务端强制才是真的——前端倒计时只是体验，→ 操作反馈方案）；
- 通道降级：短信通道失败 → 邮箱/语音备用（→ 网络方案降级三档）；
- 下发内容不含验证码明文之外的可利用信息（如「您的验证码 123456，您的手机尾号 8888」这种拼凑即可绕过的提示要审）。

### 4. 校验
- **恒定时间比较**（timing-safe equal）——逐字符提前返回可被计时侧信道爆破；
- 过期时间短（默认 5 分钟）；过期即删不复活；
- 校验失败响应**不区分**「码错误」与「码过期」（防枚举），前端统一文案。

### 5. 防爆破
- 尝试递增延迟 / 达到上限锁定 + 解锁流程；
- **失败升级**：连续失败 N 次后强制升级验证强度（叠加图形码或改用 TOTP）；
- 锁定事件进审计并可通知账号主人（「您的账号因多次验证失败已临时锁定」）。

### 6. 降级与恢复
- 第三方行为验证码服务不可用 → 降级到内置图形码或延迟放行（→ 系统能力方案降级三档）；
- 用户换手机/丢 TOTP 设备的**恢复流程**在立项时设计——恢复流程就是新的最弱认证点，强度不得低于登录本身。

### 7. 审计与隐私
- 发送 / 校验成功 / 校验失败 / 锁定全量审计，带关联 ID（→ 可诊断性方案）；
- 手机号 / 邮箱是 PII：日志与诊断包脱敏（只留尾号），→ 安全方案敏感清单；
- 限流与锁定的判定依据（IP、指纹）留存时长符合隐私声明。

## 前端纪律

- **PinInput 组件**：N 格分离输入、粘贴自动分发、自动前进/后退、完成回调由调用方决定是否自动提交（→ `ui/components/PinInput.tsx`，本批已实现）；
- **重发倒计时是事实**：以**绝对截止时间**（发放时间 + 冷却秒数）为准，各窗口从同一 endAt 推导剩余秒数——实现用 `useCountdownUntil`（相对秒数版 `useCountdown` 仅限单窗口场景，→ 状态方案）；
- 验证码输入框**不自动提交表单之外的副作用**，`autocomplete="one-time-code"`（iOS/浏览器可自动填充短信码）；
- 倒计时期间重发按钮禁用 + 剩余秒可见（→ 操作反馈矩阵登记）。

## 测试矩阵

| 维度 | 要覆盖的情况 |
|---|---|
| 限流 | 三条限流线各自触发；并发下发 |
| 爆破 | 连续错 N 次 → 锁定/升级；重放已消费的码 |
| 时效 | 过期边界；过期与错误的响应不可区分 |
| 通道 | 短信失败 → 备用通道；服务不可用 → 降级路径 |
| 无障碍 | 视障用户走音频/邮箱路径全程可用；滑块键盘替代 |
| 前端 | 粘贴分发、自动前进/后退、倒计时多窗口一致、`one-time-code` 自动填充 |
| 审计 | 全事件带关联 ID 且 PII 已脱敏 |

## 常见根因

| 表面现象 | 常见根因 | 开始实现前的预防 |
|---|---|---|
| 短信账单异常暴涨 | 无三线限流、重发无冷却 | 服务端三线限流 + 冷却 |
| 验证码被脚本爆破 | 无尝试计数、无失败升级 | 尝试计数 + 升级策略 |
| 机器人照过 | 图形码前端渲染、简单图形码当主力 | 服务端渲染 + 行为验证码 |
| 换设备后验证码永远不对 | 未绑定会话/设备上下文 | 存储绑定发放上下文 |
| 时序攻击逐位试出验证码 | 逐字符比较提前返回 | 恒定时间比较 |
| 视障用户卡死在登录 | 图形码无替代路径 | 无障碍替代必选一 |
| TOTP 老是失败 | 服务器未处理时钟漂移 | 时间窗容差 + HLC（→ 网络方案） |
| 日志里全是完整手机号 | PII 未脱敏 | 排除清单（→ 可诊断性方案） |

## 给 AI 的实施约束模板

开始实现时，可要求 AI：

> 先给出威胁模型、验证码类型选型（逐场景记录理由）与无障碍替代路径。答案生成与校验全在服务端、密码学随机、只存 hash、绑定发放上下文、一次性 + 尝试计数；三条限流线服务端强制，重发冷却服务端裁决；校验恒定时间比较，失败响应不区分原因；失败升级与锁定进审计；通道降级与恢复流程显式设计。前端只做 PinInput 输入体验（粘贴分发、自动前进、倒计时事实化、`autocomplete="one-time-code"`），不参与答案的生成与判定。日志与诊断全脱敏 PII。实现后跑测试矩阵（限流/爆破/时效/通道/无障碍/审计），并明确列出未覆盖的攻击面。

方案确认后再改代码；第三方验证码服务的能力边界随服务版本核实，未验证标注待验证。

## 五档定位

- **一档**：威胁模型 + 类型选型 + 无障碍替代路径决策（不选也要登记）。
- **二档**：全链路七环落地、三线限流、PinInput 与倒计时。
- **三 / 四档**：失败升级、通道降级全量、审计与隐私审查（→ 主大纲四档安全各条）。
